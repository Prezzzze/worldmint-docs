Translating your game¶

You write your game in your language. To offer it in English, Spanish or German as well, add these languages and fill in their translations: yourself, cell by cell, or the agent, in one click. No code is needed.

Choosing the game's languages¶

With nothing selected in the scene, the properties show the game settings. In the Game languages section:

  • Original language: the language you write the lines, the messages and the title in. Usually yours.
  • Add a language: each added language is offered to players. The cross next to a language removes it; its translations stay in the project, and adding it back finds them again.

The agent can do it too: "put my game in English and Spanish".

Which language the player sees¶

When it starts, the game picks the player's language:

  1. the one they chose last time in the menu options;
  2. otherwise the Windows language, if the game offers it (a Canadian English Windows gives English);
  3. otherwise the original language.

With the Menu system, the Options button shows a Language row: each click moves to the next language, and everything on screen updates. The game remembers it for the next plays.

A text without a translation shows in the original language: a half-translated game stays playable.

The Translations window¶

The Game > Translations menu (or the Translations... button of the game languages) opens the list of every text the player sees, found automatically:

  • the systems' texts: the lines and answers of the Dialogue, a character's displayed name, the messages and ending text of the Trigger, the title-screen title of the Menu, an Interaction prompt's text, the item kinds of the Inventory, the resources, tools and verbs of Harvesting, a Shop's name, money and items, the titles, descriptions, steps and rewards of the Quest log;
  • the systems' own texts: "Play" and "Options" of the Menu, "Buy" of the Shop, "Quest log", "Map"... The Where column says "system text". They already exist in French and English: their cell shows that text in grey, and the game shows it until you write another one. In the other languages, they wait for their translation like the others;
  • the game's title, and the names of the controls you named;
  • the scripts' texts written with game.t("...").

There is one column per offered language. A red cell is waiting for its translation: click it, type, then press Enter. At the top, each language says how many texts it still lacks; Only what is missing hides the ones already translated. The Where column says where each text appears. A changed translation is undone with Ctrl+Z (and comes back with Ctrl+Y), like any change in the editor.

Asking the agent¶

The Ask the agent to translate button sends a request to the agent: it reads the missing texts, translates them keeping the game's tone, and fills in the tables. The cells fill in before your eyes; you can then correct any of them.

Formatting stays

A text like [b]Garde[/b] or Il faut : {outil} keeps its tags and marks in its translation: [b]Guard[/b], You need: {outil}. The agent knows it; if you translate yourself, copy them.

Where translations are stored¶

Each offered language has its table in the project, in the translations folder: translations/en.json for English, translations/es.json for Spanish. One line per text: the text as written in the game, then its translation.

{
  "Bonjour, voyageur.": "Hello, traveller.",
  "Halte !": "Halt!"
}

The file can be read and corrected with any text editor, and compares well in Git. If you change an original text, its translation does not follow: it shows in red again in the Translations window.

The exported game takes these tables with it.

For scripts¶

A script passes every text it shows through game.t: game.hud_text("score", game.t("Coins: {1}", coins)). {1}, {2}... are replaced after the translation, so the word order can change from one language to another. The systems' texts are already translated. The scripts reference details game.language, game.languages and game.set_language.
