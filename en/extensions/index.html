Writing an extension¶

An extension adds a complete tool to WorldMint without touching the engine: the city generator is the first one. It lives in its own folder, extensions/<id>/, and only uses what the engine offers it. The engine itself knows no extension.

This page is for people who write WorldMint's code. To use an extension, there is nothing to do: it shows up in the editor by itself.

An extension's folder¶

extensions/<id>/
  extension.json      its identity
  <id>_extension.cpp  the file that registers it at startup
  moteur/ editeur/ agent/ contenu/ essais/   (depending on what it does)

extension.json says what it is:

{ "id": "ville", "name": "Ville", "version": "0.1.0", "minEditorVersion": "0.4.0", "paid": true }
  • id: the name of its folder and of its place in the scene; lowercase letters, digits, _ and -.
  • minEditorVersion: the oldest WorldMint version it works with. An older version refuses it and says which version is needed.
  • paid: true for a paid extension.

Building it¶

In CMakeLists.txt, an option turns it on, and worldmint_extension(<id> <sources>...) adds its sources to the editor and to the tests:

option(WORLDMINT_EXTENSION_VILLE "Builds the Ville extension" ON)
if(WORLDMINT_EXTENSION_VILLE)
    worldmint_extension(ville extensions/ville/ville_extension.cpp)
endif()

Its extension.json is copied into the program: the file that registers it reads it through kExtensionManifest (#include "extensions/<id>/extension_manifest.h").

Registering it¶

At startup, the extension introduces itself to the registry, with what it brings:

engine::ExtensionRegistry::instance().add(info, editorTools, agentTools, derivedTiles);
  • An editor tool (EditorToolHook): a section, placed with the world settings (where the terrain lives), when nothing is selected. It receives the scene, the history (every change goes through a command that Ctrl+Z undoes), the project folder and the view. Its title is translated like the rest of the editor.
  • If it works in the view (viewport), it also has its button in the tool bar, under the terrain tools (tooltip). Picked, it receives the clicks of the view and its options bar opens at the bottom of the view (options). It draws over every view, picked or not.
  • Its long work runs in the background (frame, every frame): it says so in the fixed status line (status), and asks the editor to read its derived objects again when their cache changed (derivedChanged). The editor never freezes.
  • A tool built only in the editor (it draws with ImGui) is added from its own file, with addEditorTool(id, tool).
  • Agent tools (AgentToolHook): a name prefixed by the extension, an English description, the schema of their arguments. They join the agent's tool list.
  • Agent guides: extensions/<id>/agent/guides.json (in the format of agent/guides.json: the guides, their "when" line, the guide of each tool) and one .md file per guide. They are copied into the program (extension_guides.h) and join the agent's guides when the extension is allowed. tools/check_agent_guides.py checks them, like the others.
  • Derived objects (DerivedTileHook): what the extension produces for one tile of the world.

Its data in the scene¶

Each extension has its place in the scene file, under its id:

"extensions": { "ville": { ... } }

It reads and writes whatever it wants there. This place is read and written back unchanged, even when the scene is opened without the extension: nothing is lost.

Derived objects¶

What an extension produces (the streets of a city, for example) is not saved in the scene. For each tile, it is stored in the project cache, <project>/.worldmint/<id>/<tile>/: its files, and objects.json, the list of objects. On load, these objects are read back from the cache and carry generatedBy: a game without the extension still shows them.

They can be looked at and selected, but not changed, moved or deleted, neither in the editor nor by the agent: they never enter the history. The properties say which extension produced them. To change them, change the extension's data, with its tool.

The export takes this cache along into data/.worldmint/<id>/ (never .worldmint/cache/): the exported game reads the derived objects back on load, without the extension. A scene only receives the objects of the extensions that have data in it.

The licence¶

A single function decides whether an extension is open: extensionAllowed(id). Today, it is open as soon as it is built and accepts this WorldMint version. Later, it will also read the WorldMint account's licence. An extension that is not open adds nothing: no tool, no derived object; its data stays kept in the scene. The editor says so once at startup, in its log, with the reason (a WorldMint version that is too old, a missing licence).

Tests¶

An extension's tests go in extensions/<id>/essais/ and run with WorldMint's own, for every version. The hooks themselves are tested in tests/test_extensions.cpp.

They are added to engine_tests only, next to worldmint_extension(...):

target_sources(engine_tests PRIVATE extensions/ville/essais/test_city_plan.cpp)

The City example¶

The “Cities and roads” extension (its id stays ville) keeps its plan (street profiles, nodes, segments) in its place in the scene, and changes it only through an undoable command. Its derived-object hook produces, for each tile its streets touch:

  • chaussee.glb: the roadway, the sidewalks with their curbs, the road markings;
  • empreinte.txt: the fingerprint of what the tile draws. A tile whose fingerprint has not changed is not rewritten: moving a point only rebuilds the tiles it touches. It includes the city computation version (ville- and 12 characters), the fingerprint of the city engine's sources and of the data it reads, computed at build time: a new WorldMint version that changes the generation rebuilds every tile by itself;
  • one derived object, ville/<tile>/chaussee, which shows that model.

The .glb format is glTF 2.0: the engine writes it itself (assets/glb_writer.h) and reads it back like any other model.

Its editor tool, City (Streets and Districts modes, plan view, "Generate a city…": see The city), only changes the plan, through that command: each gesture is one step. Its frame hook rebuilds the cache on a thread, from a copy of the scene, and says "Updating the city…" or "Generating the city…" meanwhile: the editor never freezes. The plan view uses frameFromAbove.

Its agent tools do the same, one undoable step per call, with refusals in English:

Tool What it does
city_generate A whole city (center, size or area, seed, districts; replace to replace the existing city); or a town in a zone (outline, or center, size and angle), with ambiance and name, next to the others.
city_town_set A named town (town): rename it (name), lay it out again (regenerate, seed), delete it (delete).
city_road_add A street between two points or two nodes (from, to, via), with its profile and name.
city_road_set The profile, name, path or crossing of a street (a refused bridge), its deletion; a node (roundabout, position).
city_get The plan in less than 3,000 characters, by pages: streets, nodes, districts, styles.
city_check Crossings without a junction, slopes too steep, segments too short, unwanted dead ends, orphan overrides, parcels without access.
city_district_set Add a district, change its style, name or outline, another draw, delete it.
city_style_set A district style or a street profile: create it from another one, set its values, delete it.

Its guides, city and city-districts (extensions/ville/agent/), tell them to work at the level of the plan and to check with a picture. Its starting data (the seven district styles, the lists of street names) is in extensions/ville/contenu/, copied into the program at build time.

What the free engine keeps¶

The City is a paid extension ("paid": true). The engine stays free and holds nothing specific to the city. The hooks it uses are generic, and serve any extension:

  • the registry and the licence (extensionAllowed), the editor tool (section, palette button, options bar, view clicks, background work, status line), the agent's tools and guides;
  • the place in the scene, read and written back intact without the extension;
  • derived objects and their cache, taken along by the export and read back without the extension: a game made with the city plays everywhere. A derived object can name a model of the project's library (DerivedObject::asset) and say it lies on the ground (groundCover): its simplified versions seen from afar do not go under the ground;
  • plant-free areas of the terrain (Terrain::clearings): the terrain's sowing avoids the areas an extension gives it (the roadway, the sidewalks), and the plants come back when the area goes;
  • the framed top view (frameFromAbove);
  • an extension's content as data (contenu/*.json), copied into the program by worldmint_extension.
