Projects and scenes¶

A project¶

A project is a folder that holds your whole game. It can be moved, copied, sent or backed up like any folder, without repairing anything:

My game/
  My game.worldmint    the project file: the whole game and its start scene
  scenes/              the scenes (.wmscene)
  assets/              the models, sounds and images the game uses, copied from your library
  AGENT.md             optional: the agent's rules for this project
  .worldmint/          working files: the conversation with the agent, automatic backups, deleted scenes
  • Create: File > New project.... The creation assistant then offers its help.
  • Open: File > Open project..., then the .worldmint file.
  • Find it in File Explorer: File > Open project folder.
  • A scene outside a project (an old file): File > Create a project from this scene... makes it a project, copying its models into it. The original scene is not touched.

When you use a model from the library, its file (and those it names, like its textures) is copied into assets/. A file already in the project is never overwritten: changing the library does not change the project.

A project made by a newer version of the editor does not open: update the editor.

The whole game and each scene¶

A game can have several places: the outdoors, the inside of a house, a cave, levels that follow each other. Each place is a scene. Some things apply to the whole game, others to each scene:

The whole game Each scene
The played character: its model, animations, settings Its objects, terrain, vegetation, water
Activated systems and their settings for the whole game The systems placed on its objects, with their values
The game's scripts Its light and sky
Controls, window, simulation Its placed cameras, and the one that opens it
Reusable objects Its arrival points
The start scene

Scripts keep running when the player changes scene, and keep their variables.

Managing scenes¶

In the Scene tab, the Game scenes section (see The Scene tab):

  • + creates a new scene;
  • a click opens a scene (the editor first offers to save the open one);
  • right-click: Open, Rename, Duplicate, Delete, Start the game here.

The word Start marks the scene where the game starts. F5 always plays from the scene you are looking at, to try it; the exported game starts on the start scene.

A scene name cannot contain < > : " / \ | ? *, nor start or end with a dot or a space, and has 80 characters at most.

Linking scenes¶

To have a door lead inside a house:

  1. In the house's scene, create an arrival point (Object > Create > Arrival point, or right-click in the list): this is where the player will appear, facing the arrow. Name it (for example "Entrance").
  2. In the start scene, activate the Passage system (Game tab), and place it on the door.
  3. In the door's properties, Systems section, choose the Scene it leads to, then the Arrival: an arrival point of that scene.

The scene list then shows next to the door → House · Entrance, in red if the scene or the arrival does not exist. An arrival point's properties list the passages that lead to it. The player takes the passage with the interaction key (E by default), or by walking into it if Taken by walking into it, without a key is checked: see the Passage system. Think of the way back: a passage in the house, leading to an arrival point in front of the door. The player keeps everything when changing scene (inventory, health...).

A script can also change scene with game.go_to: see the scripts reference.

Before playing, if the scene you start has neither the player's character nor an arrival point, the editor warns you ("An arrival point is missing"): the player would appear anywhere. Create an arrival point places one where you are looking; Play anyway starts the game.

Saving and recovering¶

  • Ctrl+S saves the open scene, and the whole game with it.
  • An automatic backup keeps a separate copy every 60 seconds (set in the Preferences), without touching your files. The status bar shows the time of the last one.
  • If the editor closed without saving, it offers Recover your work? on the next launch. After Recover, save to keep it.
  • A deleted scene is set aside in .worldmint/: nothing is lost.

Large worlds¶

A map of several kilometers is heavy: saving all of it on every Ctrl+S would take time. The Large world setting (nothing selected, Technical settings section) stores the scene in pieces of 256 m, in files next to it:

scenes/
  Ville.wmscene       the scene: its settings, and the list of its pieces
  Ville.tuiles/       one file per 256 m piece: its objects, its relief, its retouched plants
  • Nothing changes in the editor: you work as before, and you never see the pieces.
  • Only the pieces that changed are rewritten: a moved object or a brush stroke on the relief only saves the piece it touched. Undoing a brush stroke also keeps only the pieces it touched.
  • Nothing is lost if the computer stops while saving: the scene reopens as it was before, or as it is after, never half-way. If a piece is missing or damaged (by an incomplete copy, for example), the scene refuses to open and says which one, without changing anything.
  • Switching to a large world keeps the previous file next to it (Ville.wmscene.avant-grand-monde.bak). Going back (unticking) writes the scene again as a single file and sets the pieces aside (Ville.tuiles.bak).
  • Copying or sending a scene: take the .wmscene file and its .tuiles folder. Renaming, duplicating or deleting a scene from the editor takes them together.
  • Export takes the pieces with the game, and the exported game reads them all.

A small scene does not need this setting: it stays a single file.

To work on one part of the map without seeing the rest, and to lock what is finished, cut it into sectors: see The Scene tab. Sectors are saved with the scene; working on one and saving still rewrites only the pieces that changed.

What sleeps far from the player¶

In a large world, the game only brings to life what is around the player. Beyond the Activity radius (300 m by default, under Large world), in squares of 256 m, objects fall asleep: they are still there and can be seen, but characters stop walking, moving objects stop, animations and zones wait. When the player comes back, they wake up as the world kept them. The radius is the same on every computer: your game plays the same everywhere.

  • What must live far away (a messenger crossing the map, a boss on patrol): tick Always active in the object's Details, or Objects always active on a system's card, in the Game tab. Keep it for few objects: what stays awake far away costs at every moment of the game. The editor shows how many there are, under Activity radius and in the object's Details, in red beyond Always active, advised (100 by default); the agent is warned too.
  • Scripts only see what is awake when they look for objects; they can ask for the sleeping ones too, and learn who falls asleep and who wakes up (see the scripts reference, game.awake).
  • A small scene never sleeps: everything stays awake.
