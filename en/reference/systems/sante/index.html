Health¶

Health and armor for the objects that carry it: the player, a group of skeletons, a boss, each with its own values. Shows nothing: add "Health bar" to see it.
Identifier sante
Version 6
Placed on objects yes

Settings for the whole game¶

In the Game tab, Systems section, by opening the system's card.

Setting What it does Name in code Type Default Limits or choices
Armor calculation How armor reduces damage, in the whole game. Simple: an armor of 25 stops 25 % of each hit (90 % at most). Curve: armor is counted in points, each one counting a little less than the one before, for a role-playing game with a long progression. calcul Choice in a list Simple: armor is a percentage pourcentage: Simple: armor is a percentage
courbe: Curve: armor / (armor + K), like Diablo or WoW
Curve: the armor that stops half the damage (K) With the curve calculation: the armor that stops half the damage. With 100, an armor of 100 stops half, 300 stops three quarters. constante Number 100 from 1 to 1 000 000

Settings on each object¶

In the Properties of an object or folder that carries the system, Systems section. A folder passes its values on to what it contains; an object can change a value for itself only.

Setting What it does Name in code Type Default Limits or choices
Health points Its health at the start of the game, which is also its maximum health. At zero, it dies. points_de_vie Number 100 from 1 to 1 000 000
Armor (in % or in points, depending on the game's calculation) What reduces each hit taken. With the simple calculation, a percentage: 25 stops 25 %. With the curve calculation, points: see the game setting. armure Number 0 from 0 to 1 000 000
Invulnerability after a hit (s) After a hit, it loses no health for this many seconds: hits too close together count only once. 0: every hit counts. invulnerabilite Number 0.5 from 0 to 60
Remove the object when it dies (not the player) Ticked: the object leaves the game when it dies. Unticked: it stays there. The player is never removed. detruire_a_la_mort Yes or no no

Events¶

The descriptions come from the code.

What it announces¶

Event Fields Description
sante.change cible (id), vie (number), max (number) An object's health changed, or is announced once when the game starts.
sante.mort cible (id), source (id?) An object's health reached zero. What happens next belongs to the game: the health module does nothing else, unless its setting says to destroy the object.
sante.pare cible (id), source (id?), montant (number) A hit was blocked by a guard: montant is the damage it stopped. For a clang, sparks, a stamina cost.

What it listens to¶

Event Fields Description
scene.change depuis (text), vers (text) Sent by the engine once the player has arrived in another scene of the game (game.go_to, or a passage). Scripts keep running across scenes: this is when a module looks at the objects of the new scene.
sante.blesser cible (id), montant (number), source (id?) Ask the health module to remove health from an object.
sante.soigner cible (id), montant (number) Ask the health module to give health back, up to its maximum.
sante.garde cible (id), part (number), angle (number) An object protects itself, or stops (part 0): hits coming from in front of it, within angle degrees, lose part of their damage (0 to 1) before its armor. A hit without a source cannot be blocked.

Points a script can replace (game.override)¶

The descriptions come from the code.

  • sante.degats: function(default, cible, brut, source, retenue) -> the health removed. brut: the raw damage sent; retenue: the share stopped by the target's armor (0 to 1). The default returns brut * (1 - retenue). For critical hits, weaknesses, a boss that only takes fire.

What the agent knows about this system¶

The text the agent reads before using this system.

Health (sante)¶

Health and armor for the objects that carry this system: place it on the player, on an enemy, or on a group so that all its children have it. Each object or group has its own values: an early skeleton and a final boss do not have the same health. It decides nothing for the game: it removes and gives back health, and announces changes and deaths.

  • Place it with systems_attach, and set each group's values with systems_set: points_de_vie, armure, invulnerabilite, detruire_a_la_mort. A child can change one value for itself; the rest comes from its group.
  • For the whole game (modules_set): calcul is pourcentage (armor 25 stops 25 % of each hit, at most 90 %) or courbe (armor in points, stopping armor / (armor + K): with K = constante = 100, 100 armor stops half, 300 stops 75 %). Choose courbe for an RPG with a long progression; tell the user.
  • Hurt something: game.emit("sante.blesser", {cible = id, montant = 10, source = attacker}). montant is the raw damage: the target's armor is applied here.
  • Heal: game.emit("sante.soigner", {cible = id, montant = 10}). For potions, food and springs, use the module soins.
  • Guard: game.emit("sante.garde", {cible = id, part = 0.7, angle = 120}) makes hits from in front lose 70 % before armor, until sent again with part = 0. The player's blocking comes from combat.basique: use this only for a guard of your own, such as a shielded enemy. Announced by sante.pare.
  • This module shows nothing on screen. For the player's health bar, add barre_de_vie; for anything else, listen to sante.change (cible, vie, max). It is announced once for everyone on the first step, then on each change.
  • React to a death: listen to sante.mort (cible, source). What a death means (game over, loot, respawn) belongs to the game, and only if the user asked for it.
  • Objects cloned during the game from an object carrying it have its values.

Several players¶

One for the whole game: every object carrying it has its own health, each player's character included. A player is never destroyed at death.
