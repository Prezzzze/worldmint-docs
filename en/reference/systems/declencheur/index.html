Trigger¶

"When… then…" rules without writing code: when the player enters a zone, uses a lever, when a boss dies… then a door opens, a chest appears, the game is won. With ready-made actions, and those written for this game.
Identifier declencheur
Version 10
Placed on objects yes

Settings for the whole game¶

In the Game tab, Systems section, by opening the system's card.

None.

Settings on each object¶

In the Properties of an object or folder that carries the system, Systems section. A folder passes its values on to what it contains; an object can change a value for itself only.

Events¶

The descriptions come from the code.

What it announces¶

Event Fields Description
besoins.remplir besoin (text), montant (number) Ask the besoins system to raise a need by its name, without using anything up: a meal at an inn, a Trigger rule, a script.

What it listens to¶

Event Fields Description
zone.entree cible (id), qui (id), joueur (id?) Something entered a zone (an object carrying the zone system): a player, a character or a moving object, depending on what the zone detects (joueur: every player). joueur is set when qui is a player. Announced by the engine.
zone.sortie cible (id), qui (id), joueur (id?) Something left a zone. Not announced for an object removed from the game while inside.
interaction.utiliser cible (id), joueur (id) The player used the object in reach: a door, a merchant, an item to pick up. Whoever owns that object decides what it does.
sante.mort cible (id), source (id?) An object's health reached zero. What happens next belongs to the game: the health module does nothing else, unless its setting says to destroy the object.
articulation.cassee cible (id), autre (id?) A joint (an object carrying the articulation system) gave way: pulled harder than its breaking force, or broken by the Trigger or game.joint_break. autre is the object it was attached to, missing when attached to the world. Announced by the engine.

Trigger (declencheur)¶

"When… then…" rules placed on objects, so the user gets a game reaction without code: when the player enters a zone, uses a lever, when a boss dies, at the start, after a time, or when an event happens… then show, hide or destroy an object, make a copy appear, teleport the player, go to a scene, end the game, play a sound, play a full-screen video, muffle or mute the sound, show a message, push a moving object, send an event — or run a reusable action written for this game.

  • Place it on the object the rule is about (systems_attach), with its rules in regles: a list, one object per rule. Prefer it to a script for these reactions: the user sees and changes the rules in the object's properties.
  • Each rule: quand (entree, sortie: the object carries zone; utilise: it carries interaction; mort: it carries sante; debut; delai with secondes; evenement with evenement, an event name), fois (une or chaque), attente (seconds before acting), action, and the fields of that action:
  • cible (an object id; empty: the object carrying the rule) for montrer, cacher, basculer, detruire, copier, teleporter (the player goes to it), solide, traversable (on a zone: switches it on or off), son, pousser.
  • copier: lieu (an object where the copy appears; empty: where the copied object is). Usually the copied object is a hidden template.
  • animation: frise (an animation's id, made with timeline_set) and fin (optional: an event sent when it ends, for another rule). cinematique: cinematique (a cutscene's id) and fin. arreter_animation: frise.
  • scene: scene and arrivee. finir: resultat (won or lost) and texte. message: texte, duree. son: son (a sound file, from assets_search kind "sound"). assourdir: groupe (a sound mixer group, or master for all the sound), assourdi (0 clear again, 1 under water), fondu (seconds). couper_son: groupe, coupe (true mutes, false brings it back). video: video (an MP4 file, from assets_search kind "video"), passer (true: the player can skip it), fin (an event sent when it ends or is skipped, to chain the next rule; a video file that cannot be read still sends it), groupe_video (the mixer group of its sound, voice by default: the music lowers under it). pousser: force, hauteur. envoyer: nom (sends that event with cible, source and qui). remplir_besoin: besoin (a need's name, as in the besoins list: « Fatigue ») and montant: the player who triggered the rule gets it back (resting by a fire, a meal at an inn); a need switched off does not change.
  • cible also for ouvrir, fermer (a hinge or slider of the articulation system: a door, a drawbridge, an elevator; its motor drives it to its open or closed stop), casser (its joint gives way and it falls), chiffon (a character falls limp as a ragdoll) and relever (it gets back up).
  • effet: effet (objet: lights again the effect the target carries with the particules system; or a ready-made effect played once on the target: eclats, eclats_bois, eclats_pierre, poussiere, feu, fumee, explosion, etincelles, impact, magie, pluie, neige) and taille_effet (its size, 1 by default). arreter_effet: puts out the effect the target carries (a campfire), and the looping effects scripts put on it.
  • quand casse: the object's joint broke (it carries articulation): a bridge gives way, then a message.
  • cible (a placed light, created with a light field) for allumer (switch on), eteindre (switch off), basculer_lumiere (on or off in turn) and couleur_lumiere, with couleur ("#rrggbb"): a lamp lit by a lever, an alarm turning red.
  • Example, a pressure plate that opens a door: a zone box named Plaque, and on it {"regles": [{"quand": "entree", "action": "cacher", "cible": "<door id>"}]}.
  • Under water: a zone box over the water with {"regles": [{"quand": "entree", "fois": "chaque", "action": "assourdir", "groupe": "master", "assourdi": 1}, {"quand": "sortie", "fois": "chaque", "action": "assourdir", "groupe": "master", "assourdi": 0}]}.
  • A brazier lit by a lever: the particules system on the brazier with boucle true, and on the lever {"quand": "utilise", "fois": "chaque", "action": "effet", "effet": "objet", "cible": "<brazier id>"}; another rule with arreter_effet puts it out. A barrel that explodes when hit: {"quand": "mort", "action": "effet", "effet": "explosion", "taille_effet": 2} then a rule that destroys it.
  • A lever: interaction on the lever and a rule {"quand": "utilise", "fois": "chaque", "action": "basculer", "cible": "<door id>"}.
  • A lamp switched by a lever: {"quand": "utilise", "fois": "chaque", "action": "basculer_lumiere", "cible": "<light id>"}.
  • A drawbridge that lowers when the lever is used, then a chest appears: {"quand": "utilise", "action": "animation", "frise": "pont_baisse", "fin": "pont_en_bas"} on the lever, and {"quand": "evenement", "evenement": "pont_en_bas", "action": "montrer", "cible": "<chest id>"}. A door that moves (slides, swings) is an animation, not a reusable action.

Reusable actions: when the user wants an effect no ready-made action does and that is not a set movement (a set movement such as a door that slides, a bridge that rises or a light that blinks is an animation: timeline_set, then the action animation), write it ONCE as a reusable action, never as a one-off script tied to one object: - A game script named action.<id> (scripts_set; id: lowercase letters, digits, _), which starts with its description in JSON between --[[action and ]]: label and description in fr and en, and fields (settings like a module's: key, type number/text/boolean/choice/object/sound/video/scene, default, label in fr and en, min/max, options; a number takes decimals unless it has "integer": true, for a count). - Its code listens to action.<id>: game.on("action.porte_glissante", function(e) ... end). e.cible is the rule's target (or the object carrying the rule), e.source the object carrying the rule, e.qui who triggered it, and each of its fields by key. - It then appears in the "Then" list of every Trigger, with its fields, next to the ready-made actions; a rule uses it with "action": "<id>" and its values in parametres. The user can reuse it on other objects without asking you again: tell them so. - Example: --[[action {"label": {"fr": "Porte qui glisse", "en": "Sliding door"}, "description": {"fr": "La cible glisse sur le côté.", "en": "The target slides aside."}, "fields": [{"key": "distance", "type": "number", "default": 2, "min": 0, "max": 50, "label": {"fr": "Distance (m)", "en": "Distance (m)"}}]} ]], then the code.

Several players¶

One for the whole game: "the player" of a rule is the one who triggered it (who entered the zone, who used the object); its message is shown to that player only, and teleporter moves that player. Rules at the start or after a delay concern no one in particular: their message is shown to everyone.
