Menu¶

The title screen when the game starts, and the pause with Escape: Resume, Options (in sections: sound, display with the graphics and, for a translated game, the language, controls), Quit. The game stops while the menu is open, and it takes the look of the Interface system. A game with the Multiplayer setting also has Host and Join there.
Identifier menu
Version 19
Placed on objects no

Events¶

The descriptions come from the code.

What it announces¶

Event Fields Description
menu.jouer — The player left the title screen with Play: the game really starts. For an intro message, a music, a timer that should not run behind the title.
menu.pause ouvert (boolean) The pause menu opened (ouvert true) or closed (ouvert false). The world is stopped while it is open.

What it listens to¶

Event Fields Description
hud.clic cible (text), joueur (id?) A button of the HUD was clicked: pressed, then released on it; or chosen with A (Enter) while it has the gamepad or keyboard focus; or the window's back button (back = true), with B (Escape). cible is the button's key (game.hud_button), joueur the player who clicked (a guest clicks on their own computer; the host plays the click). Announced by the engine, before the scripts' on_update of that step.
profil.demande essai (number), raison (text), propose (table?) Sent by the engine in the game of a player who is joining (before entering, while their own scripts still run: the title screen, the Menu), when the host wants them to create their character because they have none in this world (game setting Players' characters, ADR-020 § 18). essai is 0 the first time, then the number of refused tries; raison the game's text explaining the last refusal (translate it with game.t); propose the look kept on this PC (setting Same look everywhere), to offer in advance. The creation screen sends the choices with game.profile_send(table).
scene.change depuis (text), vers (text) Sent by the engine once the player has arrived in another scene of the game (game.go_to, or a passage). Scripts keep running across scenes: this is when a module looks at the objects of the new scene.

What the agent knows about this system¶

The text the agent reads before using this system.

Menu (menu)¶

The title screen when the game starts, and the pause menu with Escape: Resume, Options (the master volume and one volume per group of the sound mixer: music, effects, ambience, voice, ui and the game's own groups; the graphics; a new key for every control), Quit. Add it once with modules_add; it is for the whole game, not placed on objects. Use it whenever the user wants a title screen, a pause or an options menu: do not write one in a script.

  • The world stops while the menu is open (game.pause): the player, enemies, physics, animations and game.time. The menu takes the look of the interface system: change the style there, not here.
  • Game settings (modules_set): ecran_titre (title screen at start), titre (the title shown; empty: the game's title from the game settings, Window), pause (Escape opens the pause menu), options and quitter (show those buttons), voile (how dark the stopped game gets behind the menu, 0 to 1).
  • Look of the title screen and the pause (settings disposition, fond, logo, sous_titre, barre_touches); the Options screen keeps its own window:
  • disposition follows the family of the game, like the games players know. gauche (title at the top left, the buttons in a column under it, the scene alive on the right, the menu side darker): shooters, racing, strategy, survival, role-playing games. centre (the default: title and buttons in a window in the middle, the world behind): farming, party games. bas (title at the top, the buttons in a row at the bottom, the middle of the picture left clear; a short column at the bottom when there are Host and Join): a story, a puzzle game. For a role-playing game played online, the simple character creation screen (creation_personnage) is already there.
  • fond: a picture that covers the whole title screen (and the screens opened from it), cropped to the screen, never stretched: it keeps its middle on 4:3 and very wide screens. Empty: the stopped game world shows behind (the usual choice when the scene is worth seeing). Pick a wide image (1920 × 1080 or more) with its subject in the middle. logo: an image shown instead of the title text, with its proportions (a transparent PNG). sous_titre: a smaller line under the title (translated with the game's tables). Find images with assets_search and kind image, then modules_set menu with the path; never guess a file name. A missing file falls back to the world and the title text.
  • barre_touches (on by default): a strip at the bottom recalls the menu's keys on the device the player uses: « Entrée Choisir · Échap Retour » on the keyboard, « A Choisir · B Retour » on a gamepad (Retour only where a button goes back: the pause, Join). These are the engine's menu keys (Enter or A clicks, Escape or B goes back); they cannot be rebound. Its words are texts of the menu: choisir, retour, touche_entree, touche_echap, touche_a, touche_b (hook « menu.texte »).
  • The title screen and the pause are screens the system delivers (screens_get): « Écran titre » and « Pause », one of each in the game. Their shapes: Fenêtre (the window), Voile, Titre, Logo, Sous-titre, Version (the title screen), Bouton Jouer or Bouton Reprendre, Bouton Options, Groupe en ligne (Libellé du nom, Nom du joueur, Bouton Héberger, Bouton Rejoindre), Partie en ligne, Code de la partie, Bouton Arrêter en ligne, Connexion (a guest's pause), Erreur, Bouton Quitter, Barre des touches (Touches); En-tête and Bande (gauche), Bas de l'écran and Rangée des boutons (bas). Their HUD keys are « Écran titre/Bouton Jouer », « Pause/Bouton Reprendre »… (click Play in game_run with {"frames": 3, "click": "Écran titre/Bouton Jouer"}). The menu's script shows them, fills their texts and hides what the settings remove (Options, Quit, the online group…): change their look with screens_set like any screen (a style, a place, a size), never their names. disposition installs the screen's model for that layout (centre, gauche, bas): changing the setting replaces the screen, unless the user modified it; then it keeps its own layout and modules_set says so (screens_kept).
  • Styles for a UI pack (interface system, habillage): Play and Resume are bouton.principal, Quit is bouton.danger, the window fenetre.menu, the title titre.menu, the key strip panneau.touches, the veil fond.voile, the band fond.bande, the version texte.version (« Version 1.0.4 », small at the bottom right of the title screen; only when the game has a version: game settings, Publication, world_set window.version; text « version » of the menu). A style without a row of the theme takes its kind (bouton, panneau): nothing changes without a pack.
  • « Rejoindre » and « Personnage » are delivered screens too. « Rejoindre »: Titre, Onglets (Onglet Liste, Onglet Code, Onglet Adresse), Ligne de recherche (Recherche, Bouton Actualiser), Salon (what the game service says), Serveurs (a list: one Serveur row per server, keys « Rejoindre/Serveur#1 »…), Code, Adresse, Mot de passe requis, Mot de passe, Nom du joueur, Connexion, Erreur, Bouton Rejoindre, Bouton Retour. « Personnage »: Titre, Refus, Nom du personnage, Attente, Bouton Entrer, Erreur. Both have Voile and Barre des touches.
  • « Options » is a delivered screen too: Titre, Onglets (Onglet Son, Onglet Affichage, Onglet Touches), Contenu (it takes the height of the open section up to half the screen, then scrolls) with three lists: Volumes (rows Nom du volume, Moins, Volume, Plus: « Options/Moins#1 » is the master volume, then each mixer group), Choix (rows Nom du choix, Valeur: the graphics, Quality first) and Commandes (rows Nom de la commande, Touche), plus Ligne de langue (Langue), Graphismes, Ray tracing lourd, Ray tracing coupé, Ligne de lumière (Lumière), Aide de la lumière, Aide and Bouton Retour. The menu's script draws nothing with game.hud_* any more: all its screens are delivered.
  • Texts follow the player's language: the menu's own texts (Play, Options, Graphics...) are built-in texts of the system, listed by translations_get like the game's texts. Translate them there for every language the game offers; without a translation, the menu shows its French or English text. For a translated game (world_set languages), Options shows a Language row: each click moves to the next offered language, and the game remembers it. The titre setting is translated with the game's tables. To change a word, override menu.texte from a game script: game.override("menu.texte", function(default, key) if key == "jouer" then return "Commencer" end return default(key) end).
  • Options are arranged in sections, one tab each (Options/Onglet Son, Options/Onglet Affichage, Options/Onglet Touches): Sound (the volumes), Display (the language of a translated game and the graphics; only when there is something to choose) and Controls (the keys). A section taller than half the screen scrolls inside the window, which never overflows, however many sound groups or controls the game has. In game_run, click a tab before the rows of its section: only the open section is in the report's hud.
  • Graphics, in Options (Display section), for a game on screen: Quality (Low, Medium or High: shadows, lights, water, glow, terrain and plant distances, and the particles budget; the machine chooses at first, Low on an integrated chip, High on a graphics card), Upscaling (Off, anti-aliasing only, Quality 67 %, Balanced 58 %, Performance 50 %, Ultra performance 33 %; the game's own window.upscaling at first), Shadows (As quality at first, then High, Medium, Low, Off: for the sun and every light, effects' lights included; Off removes every shadow, the lightest; over the scene's shadowQuality), the upscaling method (None, FSR on every card, and DLSS (NVIDIA) only when the user provided NVIDIA's files and turned DLSS on in the game settings (Game window), on an RTX card; shown only when FSR or DLSS works there); Ray tracing (Automatic, On, Off) only on a graphics card that has it, when the game allows it (« ray_tracing » in world_set window, allowed by default). Automatic draws shadows and reflections with rays only on a dedicated graphics card in Medium and High quality; On forces it, with a short warning under the line where it is heavy (an integrated chip, Low quality); when the graphics card's memory is full, the game turns rays off by itself (classic shadows) and a short line under it says so, until the player picks another value. Under it, Indirect lighting (On at first, or Off; shape Options/Lumière, with a short line saying what it does): the light bounced by surfaces, ray traced, only in High quality (about 1 to 2 ms). Each click moves to the next value, at once. The menu uses game.graphics and game.set_graphics: a game script can call them too, but never alongside the menu's options. Not shown in game_run without capture: nothing is drawn there.
  • The player's choices in Options (the volume of each sound group, the graphics and the keys and gamepad buttons they changed) are kept from one launch of the game to the next, in the save slot menu-options: the exported game keeps it with the player's saves, the editor with the saves of its test runs. The game settings and the project are never changed by it. Do not use that slot name in a game script; game.delete_save("menu-options") gives the player the game's own volumes, graphics and keys back at the next launch. A control the game no longer has is forgotten. In game_run, saves start empty: every run begins with the game's own volumes, graphics and keys.
  • A title scene (setting scene_titre, a scene of the game; camera_titre, the name of a placed camera of that scene, optional): the title screen shows over its own backdrop, as many games do (the car in a garage, a campfire at night, the character in the light), with a very light veil. The game opens there from its start scene, through that scene's camera (camera_titre, else the scene's start camera, else its first placed camera); the player is hidden there and controls nothing, the game's HUD is hidden. Play (and Host a game) leads to the game's start scene through the usual scene change, with its fade, and menu.jouer is sent once arrived there. Host a game opens the game to guests only once the host is in the start scene: a guest who joins arrives there, never in the title scene. A test run started in the editor from another scene goes straight to that level; started from the title scene, it shows it. A scene_titre that is not a scene of the game: the title screen shows over the start scene as without it, and the game's log says why. Make it with the recipe of scenes.md (Title screen scene). The game's systems started in the start scene: in the title scene, nothing starts before Play (the hotbar and timers are hidden, manche waits for menu.jouer); jour_nuit leaves the title scene with its own light, and the game's music (sons) plays over it. The pause stays the pause: there is no way back to the title scene during a game.
  • The title screen shows only the menu, over the world: the engine hides the rest of the HUD (the hotbar, a timer, the game's drawn screens) while it is open (game.hud_only("menu."); the report marks those elements hidden), and shows it again on Play. The pause leaves the game's HUD visible behind its veil.
  • With manche: title screen → Play (or Host a game) → the round's waiting room (« Start the game » for the host) → the countdown. Never add a start button of your own.
  • menu.jouer is sent when the player leaves the title screen: start an intro, a timer or a music on it rather than in on_start, which runs behind the title. A declencheur rule can use it too ("when the event menu.jouer"). menu.pause (ouvert) is sent when the pause menu opens or closes.
  • In game_run, the title screen waits for a click on Play: show nothing else first. The report's hud gives the area of menu.jouer; click its centre with mouse and buttons (a short segment with left, then one without). Turn ecran_titre off only if the user does not want a title screen.
  • A segment {"frames": 3, "click": "menu.jouer"} clicks Play by its key, without reading its area. With « players » (several players), only the host has the title screen: click Play in the host's inputs; the simulated players are guests and play their own inputs at once.
  • Gamepad and keyboard: with a gamepad, Play (or Resume) has the focus at once; the d-pad or the arrows move it, A or Enter clicks, B or Escape goes back from the options and closes the pause (Resume and Back are the window's back buttons). While a key is being changed in the options, the menu turns the engine's navigation off (game.hud_navigation(false)), so that A, B and the arrows can be bound too.
  • The screens « Écran titre », « Pause », « Options », « Rejoindre » and « Personnage » are the menu's: do not use these screen names, nor the HUD prefix menu., in a game script.

Several players¶

One copy per player: in a game hosted online, a menu does not stop the game. A guest has no title screen (they join a game already running) and no options (their sound, display and keys belong to their own computer): only Resume and Quit, and Quit makes them leave the game.

Host and Join (several players)¶

In a game with the « Multiplayer » setting, the title screen and the pause have « Host a game » and « Join a game » (setting « en_ligne », on by default). Join opens a screen with three tabs: List (the public servers of this game and version, from WorldMint's lobby service: name, players n/max, « [password] » when locked; a search field and Refresh), Code (the short code a host gives, such as K7P-2QMX) and Address (the host's address). A password field shows when the chosen server is locked, or after a server refused with « mot de passe manquant ou faux ». While the lobby service is not set up or does not answer, List and Code say so and Address still works. A refusal shows there; a player with another version of the game than the host reads both numbers (« L'hôte a la version 1.0.4, vous avez la 1.0.3 : mettez votre jeu à jour », texts erreur_update_needed and erreur_host_outdated). While hosting, the pause says how many guests are there, the game's short code if it has one, and has « Stop the online game ». Settings « salon_code » (on: a hosted game gets a short code) and « salon_public » (off: a hosted game is not in the public list). On the title screen and the pause the buttons go Play (or Resume), Options, then the online group (the label « Your name (seen by the other players) », the name field, « Host a game », « Join a game »), then Quit. The « Your name » field (pseudo) sits right above « Host a game » and on the Join screen: the same field and the same name kept on this PC (game.network().player_name prefills it). A player's name everywhere (chat, « X joined », game.player_name) is their character's name (the « nom » sent by the character screen), else this name, else « Joueur N ». They call game.host({public, code, name}), game.join(address, password?, name?), game.join_code(code, password?), game.find_servers(text?) and game.leave_online; only the game on screen does it (in game_run, game.network() says available=false and the buttons do not show). Texts: heberger, rejoindre, adresse, rejoindre_ok, connexion, en_ligne, hors_ligne, echec, onglet_liste, onglet_code, onglet_adresse, code, mot_de_passe, recherche, actualiser, recherche_en_cours, aucun_serveur, joueurs, cadenas, salon_absent, salon_injoignable, mot_de_passe_requis, recherche_code, code_partie (hook « menu.texte »).
