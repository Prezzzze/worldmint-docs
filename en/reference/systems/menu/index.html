Menu¶

The title screen when the game starts, and the pause with Escape: Resume, Options (in sections: sound, display with the graphics and, for a translated game, the language, controls), Quit. The game stops while the menu is open, and it takes the look of the Interface system. A game with the Multiplayer setting also has Host and Join there.
Identifier menu
Version 10
Placed on objects no

What it announces¶

Event Fields Description
menu.jouer — The player left the title screen with Play: the game really starts. For an intro message, a music, a timer that should not run behind the title.
menu.pause ouvert (boolean) The pause menu opened (ouvert true) or closed (ouvert false). The world is stopped while it is open.

What it listens to¶

Event Fields Description
hud.clic cible (text), joueur (id?) A button of the HUD was clicked: pressed, then released on it; or chosen with A (Enter) while it has the gamepad or keyboard focus; or the window's back button (back = true), with B (Escape). cible is the button's key (game.hud_button), joueur the player who clicked (a guest clicks on their own computer; the host plays the click). Announced by the engine, before the scripts' on_update of that step.

Menu (menu)¶

The title screen when the game starts, and the pause menu with Escape: Resume, Options (the master volume and one volume per group of the sound mixer: music, effects, ambience, voice, ui and the game's own groups; the graphics; a new key for every control), Quit. Add it once with modules_add; it is for the whole game, not placed on objects. Use it whenever the user wants a title screen, a pause or an options menu: do not write one in a script.

  • The world stops while the menu is open (game.pause): the player, enemies, physics, animations and game.time. The menu takes the look of the interface system: change the style there, not here.
  • Game settings (modules_set): ecran_titre (title screen at start), titre (the title shown; empty: the game's title from the game settings, Window), pause (Escape opens the pause menu), options and quitter (show those buttons), voile (how dark the stopped game gets behind the menu, 0 to 1).
  • Texts follow the player's language: the menu's own texts (Play, Options, Graphics...) are built-in texts of the system, listed by translations_get like the game's texts. Translate them there for every language the game offers; without a translation, the menu shows its French or English text. For a translated game (world_set languages), Options shows a Language row: each click moves to the next offered language, and the game remembers it. The titre setting is translated with the game's tables. To change a word, override menu.texte from a game script: game.override("menu.texte", function(default, key) if key == "jouer" then return "Commencer" end return default(key) end).
  • Options are arranged in sections, one tab each (HUD keys menu.onglet.son, menu.onglet.affichage, menu.onglet.touches): Sound (the volumes), Display (the language of a translated game and the graphics; only when there is something to choose) and Controls (the keys). A section taller than half the screen scrolls inside the window, which never overflows, however many sound groups or controls the game has. In game_run, click a tab before the rows of its section: only the open section is in the report's hud.
  • Graphics, in Options (Display section), for a game on screen: Quality (Low, Medium or High: shadows, lights, water, glow, terrain and plant distances, and the particles budget; the machine chooses at first, Low on an integrated chip, High on a graphics card), Upscaling (Off, anti-aliasing only, Quality 67 %, Balanced 58 %, Performance 50 %, Ultra performance 33 %; the game's own window.upscaling at first), Shadows (As quality at first, then High, Medium, Low, Off: for the sun and every light, effects' lights included; Off removes every shadow, the lightest; over the scene's shadowQuality), the upscaling method (None, FSR on every card, and DLSS (NVIDIA) only when the user provided NVIDIA's files and turned DLSS on in the game settings (Game window), on an RTX card; shown only when FSR or DLSS works there); Ray tracing (Automatic, On, Off) only on a graphics card that has it, when the game allows it (« ray_tracing » in world_set window, allowed by default). Automatic draws shadows and reflections with rays only on a dedicated graphics card in Medium and High quality; On forces it, with a short warning under the line where it is heavy (an integrated chip, Low quality); when the graphics card's memory is full, the game turns rays off by itself (classic shadows) and a short line under it says so, until the player picks another value. Under it, Indirect lighting (On at first, or Off; key menu.lumiere_indirecte, with a short line saying what it does): the light bounced by surfaces, ray traced, only in High quality (about 1 to 2 ms). Each click moves to the next value, at once. The menu uses game.graphics and game.set_graphics: a game script can call them too, but never alongside the menu's options. Not shown in game_run without capture: nothing is drawn there.
  • The player's choices in Options (the volume of each sound group, the graphics and the keys and gamepad buttons they changed) are kept from one launch of the game to the next, in the save slot menu-options: the exported game keeps it with the player's saves, the editor with the saves of its test runs. The game settings and the project are never changed by it. Do not use that slot name in a game script; game.delete_save("menu-options") gives the player the game's own volumes, graphics and keys back at the next launch. A control the game no longer has is forgotten. In game_run, saves start empty: every run begins with the game's own volumes, graphics and keys.
  • menu.jouer is sent when the player leaves the title screen: start an intro, a timer or a music on it rather than in on_start, which runs behind the title. A declencheur rule can use it too ("when the event menu.jouer"). menu.pause (ouvert) is sent when the pause menu opens or closes.
  • In game_run, the title screen waits for a click on Play: show nothing else first. The report's hud gives the area of menu.jouer; click its centre with mouse and buttons (a short segment with left, then one without). Turn ecran_titre off only if the user does not want a title screen.
  • Gamepad and keyboard: with a gamepad, Play (or Resume) has the focus at once; the d-pad or the arrows move it, A or Enter clicks, B or Escape goes back from the options and closes the pause (Resume and Back are the window's back buttons). While a key is being changed in the options, the menu turns the engine's navigation off (game.hud_navigation(false)), so that A, B and the arrows can be bound too.
  • HUD keys start with menu.: do not use that prefix in a game script.

Several players¶

One copy per player: in a game hosted online, a menu does not stop the game. A guest has no title screen (they join a game already running) and no options (their sound, display and keys belong to their own computer): only Resume and Quit, and Quit makes them leave the game.

Host and Join (several players)¶

In a game with the « Multiplayer » setting, the title screen and the pause have « Host a game » and « Join a game » (setting « en_ligne », on by default). Join opens a screen with a field for the host's address and a Join button; a refusal shows there. While hosting, the pause says how many guests are there and has « Stop the online game ». They call game.host, game.join(address) and game.leave_online; only the game on screen does it (in game_run, game.network() says available=false and the buttons do not show). Texts: heberger, rejoindre, adresse, rejoindre_ok, connexion, en_ligne, hors_ligne, echec (hook « menu.texte »).
