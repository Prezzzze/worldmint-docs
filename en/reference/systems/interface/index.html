Interface¶

The look of the game's menus, buttons, lists and text fields: the colors of backgrounds, text and what is selected, the text size, the rounding of corners, and an image theme (an interface pack) laid on each kind of element. Everything the game shows uses them, except what a script chooses itself.
Identifier interface
Version 5
Placed on objects no
Run by the engine yes: the engine runs it itself, without a script

What the agent knows about this system¶

The text the agent reads before using this system.

Interface (interface)¶

The look of everything the game shows on screen: panels, buttons, text fields, texts. The system has no script: the engine applies it to the HUD. Add it once with modules_add; it is for the whole game, not placed on objects.

Before any interface work, read the method: guide_get with id interface (see AGENT.md).

  • Its settings (modules_set) are the default look of every HUD element: fond_panneaux (panel background), fond_boutons (button and field background), accent (hovered button, selected field, scroll bar), texte (text color) as #rrggbb colors; taille_texte (text height, a share of the screen height, 0.03 by default); arrondi (corner rounding, a share of the screen height, 0 for square corners); opacite (background opacity, 0 to 1).
  • A value a script gives (color, alpha, size, text_color) wins over the theme. To let the user restyle the whole interface from one place, do not give colors in scripts: use the theme.
  • When the user asks for a style ("dark and gold", "like a parchment", "bigger text"), change these settings instead of every script.
  • Without the system, the HUD keeps its former look (texts slightly bigger than buttons).
  • Build menus with game.hud_panel and parent (see scripts_reference): the engine places the elements, wraps texts, scrolls long lists, and announces hud.clic and hud.valider.
  • Check a menu in game_run: the report's hud gives each element's rect as the engine placed it, hidden for what is outside a scrolled panel's frame, lines for wrapped texts, and role (the theme row that dresses it). Then look at it with capture_steps.

Dressing the interface with a UI pack: the image theme¶

Rule: to dress the interface with a pack, set the theme (habillage); never lay images over the elements. No script that puts a game.hud_image on every button, bar or window: it breaks when a window moves, and those images fill the HUD sent to each guest until it is cut. The engine lays the theme itself when it draws, on every player's screen (guests included: their game has the same settings; only each element's role travels).

habillage is a list of rows (modules_set interface habillage). Each row dresses one kind of element (sorte), or one role of it (role):

sorte What it dresses Its images
panneau panels and windows image (the frame)
bouton buttons image (normal), survol (hovered), appui (pressed), grise (disabled), choisi (selected: the open tab), alerte (a refusal, for a moment)
champ text fields image (normal), actif (being typed in)
barre bars (health, XP, stamina, needs) image (the background), remplissage (the fill: laid over the whole bar then cut to the value, never stretched), cadre (a frame drawn on top)
case slots (inventory grid, hotbar) image (normal), survol, appui, grise, choisi (the chosen hotbar slot), alerte (the slot of an item refused as too heavy)
infobulle tooltips image
titre window titles image (a banner behind the title text)
defilement scroll bars image (the track), curseur (the thumb)
cadre frames laid on top of what they surround, with no background of their own: the minimap (cadre.minicarte) and the big map (cadre.carte) image (a ring or an ornate border, drawn over the map and its markers, under the player's arrow; without an image, nothing)
coche the box of a yes/no button (role coche…, such as coche.option for the yes/no choices of the menu Options screen): a small square left of the label, never stretched over the button; the button's background stays the bouton row's image (unticked), choisi (ticked), grise (disabled)

Each row also has: marge_gauche, marge_haut, marge_droite, marge_bas (the 9-slice margins, in pixels of the image: the corners keep their size, the edges stretch one way, the middle both; 0 everywhere stretches the whole image), echelle (corner size on screen, 1: one image pixel per pixel of a 1080-high screen), teinte (#rrggbb, multiplied), opacite (0 to 1), couleur_element (true: the image also takes the color the game gives the element, for a grey image made to be tinted, such as a fill tinted red for health and blue for XP), texte and texte_inactif (#rrggbb, or empty: automatic): the color of the text laid on the image (button and slot labels, titles, tooltips, the lines of a dressed window) and of greyed text. Left empty, the engine picks dark text on a light image and light text on a dark one, from the image's average brightness; text a script colors keeps its color. With a light pack (parchment, cream buttons), check the captures: set texte if the automatic choice does not suit the pack.

  • A state without its image takes the normal image, shaded by the engine (darker pressed, greyed disabled, outlined in the accent color when hovered or selected, veiled and outlined in the alerte color (#rrggbb setting, red by default) when it signals a refusal). In your scripts, alert = true on a button or panel (game.hud_set(key, {alert = false}) to end it) signals a refusal the same way. A kind without any image keeps the color drawing (the color settings above).
  • Roles. The systems tag their elements: barre.vie (health bar), barre.xp (the progression bar), barre.endurance, barre.besoin (needs), barre.volume (menu), case.inventaire (inventory grid), case.barre_rapide (hotbar slots), panneau.barre_rapide, fenetre.inventaire, fenetre.fabrication, fenetre.savoir, fenetre.quetes, fenetre.boutique, fenetre.dialogue, fenetre.personnage (progression), fenetre.construction (the building catalog), case.construction (its slots), panneau.construction (the placing panel), panneau.touches (the key bar of the building mode and of the title screen), fenetre.menu, fenetre.carte, cadre.minicarte and cadre.carte (the map frames, kind cadre), panneau.suivi_quete, panneau.annonce, panneau.file (crafting queue), titre.inventaire, titre.fabrication, titre.savoir, titre.quetes, titre.boutique, titre.dialogue, titre.personnage, titre.construction, titre.menu, titre.carte, bouton.fermer, bouton.onglet, bouton.choix (dialogue answers); champ.chat is the chat line.
  • Roles by meaning. The systems also tag their buttons by what they do, so a pack's « primary », « danger » or « reward » buttons and its « rare » slots find their place:
  • bouton.principal: the main action of a window: Buy and Sell (boutique), Make and the station's Upgrade (fabrication), Learn or Study (savoir), Spend a point (progression), Take all (butin), Upgrade at the workshop (equipement), and bouton.principal.lancer (Start, manche).
  • bouton.danger: what destroys or gives up: Abandon a quest (quetes), Reset the spent points (progression), Remove a gem when it is destroyed (equipement), and bouton.danger.jeter (Drop, inventaire; it was bouton.jeter).
  • bouton.recompense: collecting a reward. No system has such a button yet: give it to yours (role = "bouton.recompense").
  • case.rare: the slot of an item rare or better: the inventory grid, the hotbar, the equipment slots and the « Take all » window. It wins over the slot's role (a rare hotbar slot is case.rare, not case.barre_rapide). « Rare or better »: the item's rarity is at least the rank of the rarity the game counts as rare (the butin setting protection_rang, « Rare » by default); if no rarity has that name (renamed rarities), the 3rd rarity of the list and the rarer ones. Only unique copies have a rarity.
  • coche.option: a yes/no choice of the menu Options screen (ticked when yes: selected = true). In your scripts, give role = "coche.<something>" and selected = <the value> to a yes/no button: with a coche row, its box is that row's image, drawn left of the label; without one, the engine draws a plain box there (filled with the accent colour and ticked when selected); the button's background stays a button's.
  • A role without its own row takes its parent, then its kind: bouton.danger.jeter takes bouton.danger, then bouton; without any theme row, nothing changes on screen. A case.rare row without a « selected » or « hovered » image shades its own image for those states; give it those images if the pack has them. Buttons whose meaning is not one of these keep bouton or their role (bouton.fermer, bouton.onglet, bouton.choix). A row with a role is a variant: it wins for those elements; what it has no image for comes from its kind's row, with that row's margins. A role without a row takes its kind; barre.vie.boss takes barre.vie first.
  • The first word of a role is the kind: fenetre or panneau, bouton, champ, barre, case (a button or a panel), titre (a text or a panel), infobulle. In your own scripts, give role = "..." to game.hud_* (and selected = true to the open tab or the chosen slot). role = "fond.barre.vie" marks a colored backing (the dark band under a bar) that is not drawn once the theme dresses barre.vie.

  • An element whose script gives its own images (background, fill_image in a drawn screen) keeps them: the theme dresses the rest.

  • The minimap's ring. A row {"sorte": "cadre", "role": "cadre.minicarte", "image": "<the ring>"} lays it over the minimap; the dark outline the map draws by default disappears (its dark disc stays where the map does not reach). Set the carte setting cadre_marge (a share of the map's size, 0.06 to 0.12 for a thick ring) so the map stays inside the ring. A row panneau never dresses a frame; the former role panneau.minicarte no longer exists (it was drawn under the map).

  • Images go into the project. An image chosen from the library (by modules_set, or in the editor) is copied into the project and kept by its path there: the game and its export do not depend on the library folder. A theme whose images still point outside the project shows a warning in the editor, with « Copier dans le projet ».
A pack in the WorldMint format: interface_pack_apply first¶

A pack in the WorldMint format is a folder with theme.json (palette, sprites with their nineSlice margins), PNG/Default and PNG/Double, and the same base image names in every pack (panel_window, button_primary_normal, slot_square_empty, progress_track_horizontal, banner_title, minimap_frame_mint...). For such a pack, never build the rows by hand: call interface_pack_apply {"pack": "<the pack folder, or its folder name in the library>"} ("cadre": "gold" or "pond" for another minimap ring, "dry_run": true to see the reply without changing anything). In one undoable step it adds the interface system if missing, replaces habillage with every kind and role (2× images, margins doubled, echelle 0.5; banner and ring margins measured on the images), sets the colors measured on the images (the palette names do not say the color), and sets the carte system's cadre_marge to the ring's thickness. Its reply lists the rows, the colors, the base images the pack lacks (those elements keep their look) and the pack's extensions (name, size, pivot, path): lay those yourself in drawn screens (screens_set) when the game needs them. Then check the result in game_run and capture_steps as below. A pack without the WorldMint base (its own names) is refused: dress it by hand with the method below.

Finding the right images in a pack¶

Never guess a file name or a size. assets_search with kind image and the pack's name gives every image with its size in pixels; then search by what each piece is: assets_search {"query": "UI_Modern button", "kind": "image"}, then panel, window, frame, bar, fill, slot, input, tooltip, scroll, title or header, and words like hover, pressed, disabled, selected for the states. Check a candidate with asset_info (and look at it in a capture) before choosing: a frame has a border all around and a plain middle; measure its border in pixels for the margins (a 64 × 64 panel with a 12-pixel rim: 12 on each side). Prefer images of the same pack and style for every kind.

Several players¶

The interface theme is the same for every player: each one's game draws it, guests included.
