Exporting a game¶

Exporting turns your game into a standalone folder, with its .exe program, that anyone can run on Windows, without WorldMint. Like WorldMint, the game needs a graphics card that supports Vulkan 1.3, with an up-to-date driver: otherwise, it tells the player as soon as it opens.

Exporting¶

  1. Check that the game has a player (Set as player on a character): without a player, Export game... is greyed out.
  2. Give the game a title: in the game's settings (nothing selected), Game window section, Title field ("Jeu" at first). The folder and the program take this name; without a title, the project's.
  3. File > Export game..., then choose the folder to put it in.

The status bar shows "Exporting the game...", then "Game exported: ... (15 MB)", and the folder opens in File Explorer. The editor stays usable during the export.

The agent can also export the game for you.

What the folder contains¶

My game/
  My game.exe       the game
  locales/          its texts, in French and English
  data/             its scenes, and only the models, animations, sounds and images it really uses

All the project's scenes go with the game, as they are saved (the open scene, as it is on screen). The exported game starts on the project's start scene, whichever one you were looking at.

The checks¶

  • Before replacing anything, the editor runs the exported game, without a window, to check that it starts. If it does not start, the export is refused ("The exported game does not start: ...") and the previous export stays intact.
  • An export replaces the previous one in the same folder. A folder with the same name that is not an export is never overwritten ("This folder exists and is not an export"). If the exported game is still open, close it first.
  • Warnings (a file named by a script but missing, a path specific to your computer...) show in the console, starting with "Export warning", with the script's name and line.
  • A path built in pieces in a script (PACK .. "JPG/Panel.jpg") cannot be read whole by the export: it looks in the project and the library for the one file whose path ends with the written piece, and puts it in the game at the same place as in the project, where the script will look for it. If several files end the same way, or none, a warning says so: write the whole path in the script.

Players' saved games (game.save in a script) are kept between two plays of the exported game.

The game's log¶

The exported game writes what happens to it (network connections, script errors, warnings) in a log, next to the player's saves: %APPDATA%\WorldMint\<game name>\journal.txt (type this path in the Windows Explorer address bar). The previous play is kept in journal.1.txt. The log never goes beyond 2 MB per file and never contains a password or a player key. When a tester has a problem, especially in a game with several players over the Internet, ask them for these two files.

Publishing an update¶

You fixed a bug, added a level: here is how to give the new version to your players.

  1. Change the game's version: game settings (nothing selected), Publication section, Game version field ("1.0" for a new game). Digits and dots: 1.0, 1.0.1, 1.1… The Raise the version button moves to the next one (1.0.3 becomes 1.0.4). Players see it in small print at the bottom right of the title screen (Menu system), and the game's log writes it at start ("jeu : Harvest rush 1.0.4"). A script reads it with game.version().
  2. Export again: File > Export the game..., into the same folder. The new folder replaces the old one. With Also make a .zip file (Publication section, on by default), the export also writes <title>-<version>.zip next to the folder ("Harvest rush-1.0.4.zip"): the same folder, in a single file, ready to send. Files are stored as they are, without compression. Nothing is sent anywhere: you put it online yourself.
  3. Put it online, depending on where your players find the game:
    • itch.io: on your game's page, Edit game, then upload the new .zip file (and remove the old one). Or, with butler, itch.io's tool, in one line: butler push "Harvest rush" myaccount/harvest-rush:windows --userversion 1.0.4. butler only sends what changed, and players who installed the game with the itch app get the update by themselves.
    • Steam: you need a Steamworks account (Steam's developer account) and a page for the game, which costs a fee to open. The exported folder is the content of one "depot" of your game. You upload it with SteamPipe, either with the command-line tool steamcmd or with ContentBuilder (in the Steamworks kit), following the Steamworks documentation; then, on the Steamworks site, you publish that new "build" on a branch (the default branch for everyone). Steam then updates every player.
    • GOG, Epic Games Store, or your own website: send the .zip file with the store's tool, or offer it for download on your site.

Good to know:

  • Players' saves do not move: they are in %APPDATA%\WorldMint\<game name>, not in the game's folder. Keep the same game title, or the game looks for its saves elsewhere.
  • Renaming or deleting objects of the world can upset an old save: what it said about those objects no longer finds its place. Adding is safe.
  • With several players, everyone needs the same version. A player with another version cannot join the game, and the game tells them why: "The host has version 1.0.4, you have 1.0.3: update your game" (or, if the host is behind, that the host needs to update their game).
