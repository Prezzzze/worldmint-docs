Ce que fait l'agent¶

L'agent ne touche à rien en dehors de ces outils, que l'éditeur lui donne : il n'a ni accès à vos fichiers, ni aux commandes de l'ordinateur. Chaque changement qu'il fait passe par l'historique de l'éditeur et s'annule par Ctrl+Z, ou par le bouton Annuler ces modifications sous sa réponse. Dans la conversation, chaque outil s'affiche par une courte phrase : c'est la colonne « Dans la conversation ».

Ce que l'agent lit de chaque outil¶

La description exacte que l'agent reçoit pour chaque outil (en anglais).

scene_get¶

Read the scene: revision, player, world settings, scripts, a summary of the objects grouped by name (with counts, tags and asset), and one page of objects with their world bounds. Call this before editing. Use name_contains, tag, limit and offset to read other objects. To change many objects at once, you do not need their ids: entities_update and entities_delete accept a where filter.

project_rules¶

Read how to work in this editor: the method for large requests, how to prove your work, and the index of the guides of each domain (read them with guide_get). Read this first if you have not been given it. Long rules come in parts: the answer says how many, ask the next with part.

plan_set¶

Write or rewrite your plan for a large request: the user sees it in the chat, and it survives if the conversation restarts. 4 to 10 steps, in order, each with a check saying how you will prove it works. Dropping a step that is not done requires dropped_because. Steps already done keep their evidence.

plan_step¶

Update one step of your plan, by its number from 1. Mark a step doing when you start it. done requires evidence: what you actually observed that proves it works, not what you intended, and is refused while objects float. blocked requires evidence too: what stopped you.

assets_folders¶

List the folders of the asset library: their paths, how many models each one has, and how many are in formats the engine cannot read yet. Call this when the user names a pack or a folder. If what they name is not there, tell them instead of using something else.

assets_search¶

Search every folder of the asset library by words in the file path (all words must match, including words of the folder or pack name). Returns objects you can place; with kind "image", images for game.hud_image, interface screens and the interface system's image theme (UI packs, icons), each with its size in pixels; with kind "sound", sounds for game.sound and game.music (WAV, MP3, OGG, FLAC); with kind "video", videos for game.video and game.hud_video (MP4, M4V, MOV).

model_water¶

Real water in an imported model: list the flat horizontal surfaces of a placed model (each material), with looks_like_water when it is transparent and its name evokes water (pool, water, eau...: environment waterMaterialWords). With material and water=true, that surface becomes a real WorldMint water (a child water pool at its height and shape seen from above: depth tint, ripples, reflections, caustics, swimming); water=false removes it. Use it for a pool, a fountain or a pond that a pack models as a transparent plane. Then tune it with update_objects pool.

asset_info¶

Inspect an asset before placing it: real size in metres, pivot, triangles, skeleton. Check sizes: assets from different packs may not share a scale. For an animated character, bone_positions gives where each bone starts at rest, in the model's own frame, in metres (unscaled): use it to find the hand when the model has no hand bone. legs_for_feet_on_ground counts the legs the engine recognises for placeFeet.

entities_create¶

Add objects to the scene, as a single undoable step. Prefer one call with many objects over many calls.

entities_scatter¶

Fill an area with many copies of an asset in one call: a large floor, a forest, a field of rocks. pattern "grid" lays them every spacing metres and covers the size; pattern "random" places count of them, at least spacing apart, with the same result for the same seed. A single undoable step. Use this for open spaces rather than listing objects one by one.

progression_simulate¶

Read a progression curve and run its simulator (the same calculation as the game and the editor's curve editor). Give either module + setting (a setting of type curve of an installed module, such as the Progression module's level curve) or curve (an object: forme lineaire|progressive|exponentielle|tableau, base, hausse, facteur, tableau, niveau_max, paliers [{niveau, facteur}], arrondi). sources: the pace of gains, [{nom, xp, par_minute, niveau?}] ("1 level 3 wolf per minute"; without niveau the source follows the player's level); left out, those saved with the curve. Returns the XP of each level, the total XP to reach each level, and the time to reach each level (minutes). To change a curve, set the module setting with modules_set or systems_set (the value is the curve object, sources and ecart may be kept in it); aim for a total time the user asks for ("about 40 hours to the max level") by adjusting base, hausse or facteur and simulating again.

scripts_reference¶

Read this before writing a script: how game scripts work, every function they can call, and an example. Whatever rules the user's game has are written as scripts: how characters behave, pickups, doors, score, HUD, and an ending if it has one. The reference is long, so it comes in pieces: without argument, a summary (how a script works, the example, and each section with the functions it describes); then read the section you need with section, or every entry that contains a word with search (a function name, or a word such as push, zone, score). A long answer comes in parts: ask the next with part.

scripts_set¶

Create or replace a game script, as one undoable step. It runs when the game runs, and is refused if it does not compile, with the line of the error. Keep related logic in one script.

screens_set¶

Create or replace an interface screen of the game, as one undoable step: a score, an ammo bar, a help panel, a workshop menu. The user sees it and changes it with the mouse in the editor (Game tab, Interface screens): prefer it to game.hud_* calls in a script for an interface that does not change shape. The engine places it like the HUD, and makes it live without code: bound values, buttons that send their event, screens shown or hidden by an event or a control. To rename it, give its current name in name and the new one in screen.name. screen = {name, visible (shown from the start, default true), show_on: [events], hide_on: [events], toggle: a control name that opens and closes it, cursor (shows the mouse cursor while shown, for buttons), pause (pauses the world while shown), elements: [...]}. element = {name (unique in the screen, no /), kind: text|button|bar|image|panel|input, parent: a panel of the screen (it then places the element; anchor only aligns it left, center or right), anchor: top_left|top|top_right|left|center|right|bottom_left|bottom|bottom_right (the point of the screen holding it, and of the element: it stays in that corner on every screen shape), offset: [x, y] from that point in fractions of the screen (x of the width, y of the height; [-0.02, 0.03] from top_right), w, h (fractions of the width and height), auto_w, auto_h (fit the content; a button or field in a panel takes the panel's width), text ([b]bold[/b], [color=#rrggbb]...[/color]), size (text height, fraction of the screen height; left out: the Interface theme), color, text_color (#rrggbb; left out: the theme), opacity, image (a project image file), placeholder, max_length, value (bar, 0 to 1), layout: column|row|grid, columns, gap, padding, scroll, event (button: the event sent on click, with {cible = "screen/element", ecran, element}; the Trigger reacts to it with quand = evenement), then: nothing|close|open|replace|toggle and then_screen (button: what it does to its screen or another), binding}. UI pack images (assets_search kind image gives each image's size in pixels; never guess it): background (button, panel, bar: an image drawn instead of the color; button: its normal state), background_hover, background_pressed, background_disabled (button states; left out: the normal image), disabled (button: greyed out, does not click; scripts change it with game.hud_set(key, {disabled=})), fill_image (bar: the filled part, cut by the value without stretching), fill: left_to_right|right_to_left|bottom_to_top|top_to_bottom, uv: [u0, v0, u1, v1] (0 to 1: the part of the file shown by an image, or by a button's icon image; an icon in a sprite sheet of 4 x 4 cells: [col/4, row/4, (col+1)/4, (row+1)/4]), slice: [left, top, right, bottom] (a stretchable 9-slice frame for the background, an image and the bar fill: margins in pixels of the image, the corners keep their size, the edges and middle stretch), slice_edges: stretch|repeat, slice_scale (corner size: 1 is one image pixel per screen pixel at 1080 pixels high). binding = {source: event|value|system, name (the event, such as sante.change; the value a script sets with game.set_value; the system), field (the field read: vie), target (event: joueur, an object's name, or empty for anyone; system: the object carrying it, joueur by default), max_field (the field giving the maximum: max) or max (a number), format (text: "Vie : {valeur} / {max}"), decimals}. Scripts reach a screen with game.screen_show, game.screen_hide, game.set_value and game.hud_set("screen/element", {text=...}).

screens_get¶

Read the interface screens of the game. Without a name, lists them; with a name, returns the whole screen in the format of screens_set.

screen_retouches_set¶

Adjust a window or element that a system or a script draws in the HUD (inventory, crafting, shop, quests, map, dialogue, title screen, pause, options...) without touching the system: move it, resize it or hide it, for the whole game (every scene, the exported game, the dedicated server and guests), as one undoable step. The user can do the same with the mouse in the editor. Each retouch = {cle: the exact key of a HUD element (read the keys in the hud report of game_run, such as inventaire.fenetre), x, y, largeur, hauteur, cache}. largeur and hauteur are fractions of the screen width and height. x, y are the top-left corner of an element without parent, in fractions of the screen (whatever its anchor). To move the child of a panel inside that panel (a button of a menu, a slot of a window), use decalage_x, decalage_y (-1 to 1, fractions of its panel's frame): it keeps its place in the panel's flow (its neighbours and the panel do not move, the panel keeps its size), is only drawn shifted by that much, on top of its neighbours, and always stays inside its panel's frame (bounded on every screen format). Never give x, y to a child: they take it out of the flow (older games), its neighbours close up and a panel that fits its content shrinks. A child with only largeur or hauteur stays in the flow, at that size; a panel resized lays its children out again in its new frame. cache = true hides the element and its children (not drawn, not clickable; it no longer takes space in its panel). ordre (whole number from 0) = its rank among the children of its panel (0 = first; the others keep their system order around it). parent = the key of another HUD panel: the element is laid out in that panel instead of its own (a slot moved to the other column); a panel absent from the screen, or one inside the element itself, is ignored. Text and look: texte replaces the shown text of a text or button (max 200 characters, never empty; it wins over the system's translation), taille_texte multiplies its letter size (0.5 to 3), couleur its text colour, fond the background of a panel, button or slot ("#RRGGBB" or "#RRGGBBAA"), police one of the shipped fonts (inter, inter_appuye, manrope) or projet:<id> for a font the user added to the game (polices/<id>/), opacite 0 to 1 (the element and all it contains). A key ending with * (inventaire.case.*) is a pattern: it applies to every key made of that start plus one word without a dot, even when an item moves to another slot; field by field an exact key wins, then the longest pattern; a pattern takes no ordre nor parent. ancre (haut_gauche, haut, haut_droite, gauche, centre, droite, bas_gauche, bas, bas_droite) keeps an element without panel at its distance (measured at 16:9) from that corner or edge on wider or narrower screens. For a panel: marge (inner margin) and ecart (space between children), 0 to 0.5 of the screen height, aligner (debut, centre, fin) places its children on the free axis (centred slots in each grid row). Text formatting of a text or button: texte_h (gauche, centre, droite) and texte_v (haut, milieu, bas) place its text inside its own frame (each line aligned; inventaire.case.* with centre and milieu centres the text of every slot), gras, italique, souligne (true or false), taille_px = letter size in pixels for a 1080-pixel-high screen (8 to 200, scaled with the real screen height; it wins over taille_texte). ecran = the screen of a system where the retouch applies, when that system shows several screens with the same keys: the Menu system uses menu.titre, menu.onglets, menu (its panel)... on the title screen (no ecran), and on pause, options, rejoindre and personnage (ecran = that name). The hud report of game_run gives each element's screen ("screen"; its panel's screen applies to its children). A retouch applies only where its ecran is the element's screen, no ecran for none: moving menu.titre with ecran = options leaves the title screen alone. A pattern may have an ecran. Every value is optional; numbers between -1 and 2; at most 500 retouches. A key absent from the screen does nothing. Each retouch replaces the one with the same key and ecran; a retouch with only cle (and ecran) removes it; replace = true replaces the whole list. Check the result with game_run (its hud report gives each element's rect).

screen_retouches_get¶

Read the screen retouches of the game (screen_retouches_set): the HUD elements moved, resized or hidden by hand.

screens_delete¶

player_set¶

Choose the controlled character and tune it. Every field is optional and merged with the current values, as one undoable step: if any value is refused, nothing changes. animation is the state graph, and from may be "*". The first valid transition wins. Condition parameters: speed, speedFraction, verticalSpeed, grounded, airTime, jump, moveInput, run, stateTime, stateProgress, forwardSpeed and sideSpeed (m/s seen from the character: negative backwards, positive to its right), strafing (1 while it faces the camera). A state may have back, left and right clips, and the diagonals forwardLeft, forwardRight, backLeft, backRight (8 directions when the file has them), blended by direction while the player faces the camera (faceCamera, or faceCameraAction held): walking sideways and backwards. placeFeet sets the feet on slopes and steps. The default graph has the states idle, walk, run, jump_start, air, land, using clip names that only suit some models (Idle_A, Walking_A, Running_A, Jump_Start, Jump_Idle, Jump_Land): with any other model, read its clips with animation_clips and give your own graph.

sky_set¶

Set the realistic sky of the scene (sun, moon and stars at their real place for a latitude, a date and a solar hour; all the light of the scene follows), as one undoable step. Only the given fields change. Turn it on for a realistic look; pick a climate (it gives the latitude, the date and the usual weather); editorHour is the hour shown in the editor and the hour a game starts at; dayMinutes makes the hour move in game (minutes of play for 24 hours, 0: the hour stays); nightDarkness 0 is a readable cinema night, 1 a black night; nightColor and nightLight are the color (sRGB) and strength of the night sky's light, what lights the city where the lamps don't reach and the background of the night sky (a deep blue by default; a warmer or grayer color for a smoggy city, a higher strength for a brighter night); haze is the distant haze (aerosols: 0 pure air, 2 an ordinary fine day, 10 a hazy summer day, 40 a milky distance a few km away); style stylized for a cartoon game. Giving latitude or dayOfYear switches to the advanced mode; giving a climate alone switches back to the simple mode. photoSky draws a photographed sky (an equirectangular .hdr image of the project, e.g. a Poly Haven HDRI added from the online library) as the background, blended over the realistic sky (photoBlend), and by default also lights the scene with it (ambient light and reflections, photoLight); the realistic sun stays the direct light and the shadows, and photoAlignSun turns the image so its brightest point (its sun) is in the azimuth of the hour's sun. Its brightness follows the hour (that of the realistic sky); photoExposure corrects it.

mixer_set¶

Change the game's sound mixer (game settings, Sound mixer section; scene_get shows it in world.mixer). Every sound belongs to a group: music, effects, ambience, voice, ui are always there, and the user can add more (a radio, a boss's voice). groups: each item changes the given fields of the group with that id or name, or adds a group with a new id: volume 0..1 (the game's balance; the player's options menu multiplies it), muted, muffle 0..1 (always muffled, like a radio behind a wall: 0 clear, 1 under water), label (the name the user sees). remove: ids of added groups to delete (the five default groups stay). ducking replaces the automatic lowering rules: while a sound of when plays, lower goes down to level of its volume in attack seconds, and comes back in release seconds (default: voice lowers music to 0.4). terrain_generate¶

Make the scene's terrain (a map with relief and biomes), or give the existing one a new relief. Only when the user asked for a world, a map or a new relief: replacing a terrain loses the user's sculpting and painting, so it needs replace true. Objects resting on the ground follow the new relief; the vegetation of biomes that remain is kept. shape: land (hills to the edges), island or continent (one land surrounded by sea), continents (several), archipelago (islands). without_biomes: biome ids the world must not have (snow, desert...). New worlds use the natural generator: coasts with beaches and some cliffs, a sloping sea shelf, mountain ranges with ridges, valleys and foothills, small relief down to a few meters. For an island, set land_share, land_size, land_center, the ranges and the beaches here instead of sculpting them with terrain_brush.

terrain_biomes_auto¶

Place the terrain's regions (biomes) from the nature of the ground, without changing the relief: sand along the sea and lakes on a band wide on a gentle coast and nil at the foot of a cliff, rock on steep slopes, snow above an altitude (lower on shaded north slopes), forest or grassland in large zones with ragged fractal borders (from altitude, slope and a moisture noise), swamps in flat damp hollows near water, desert only if desert_share is above 0. Uses only the regions the terrain has; a missing one is replaced by its most logical neighbour. Use it instead of painting regions by hand (terrain_brush paint), after sculpting, or when terrain_check reports round or geometric regions or coasts without beach. The settings are kept with the terrain and reused by terrain_generate. One undoable step; the vegetation follows the regions. Cells of regions the user added (not a default region) are kept; default regions painted by hand are redone, since the terrain does not tell them apart.

terrain_brush¶

Change part of the terrain, like the user's brushes: raise (a hill), lower (a hollow, a valley), flatten (a building site, a square), smooth, ramp (a slope between two points, like a road up a hill), paint (give a biome to the ground: a sand path, a field). points are world [x, z] centres: several points make a stroke along them, in one undoable step (space them about a radius apart; raise and lower add up where circles overlap). Objects in the area do not move: ground them afterwards with entities_ground (the result lists them).

terrain_check¶

Measure the quality of the terrain's relief, read only: on the land above water, the share flat at one height, the share steeper than 45° and 60° with the tallest walls, bumps repeating the exact same shape (brush strokes, copies), how much of the coastline is a cliff or a gentle beach (and how much of the gentle coast has sand), regions laid as round or geometric patches, the relief by scale (small detail under 16 m, medium, large), the highest peak and the height range, and each lake (a round outline, a flat bottom or sheer sides mean it was dug by hand: remake it with terrain_lake). Every defect comes with a place in metres; it ends with a verdict (ok or to_improve) and advice naming terrain_generate, terrain_biomes_auto or terrain_brush. Run it after making or changing a terrain, and fix what it reports before saying the terrain is done. Ground flattened by a city does not count as flat. settings changes the thresholds for this call (the answer lists them with their values).

terrain_lake¶

Make a natural lake at a world point [x, z], in one undoable step: it digs a basin with a natural, irregular outline (no circle, no bubbles), shallow gentle shores getting steeper toward the middle and an uneven bottom, blends its banks into the ground around (a gentle cut on the high side, a soft embankment on the low side), and sets the water at the height of the lowest point of its rim so it neither overflows nor floats. Always use this for a lake or a pond: never dig with terrain_brush lower and fill with water_add. The lake is an object inside the terrain object. Every setting is optional except x and z; out-of-range values are refused with the reason.

terrain_river¶

Make a river from a water source at a world point [x, z], in one undoable step: from the source the water follows the steepest slope; a hollow with no way out fills up into a lake (a normal lake object) and the water leaves by the lowest point of its rim; it stops in the sea, in an existing lake or at the map edge. It digs the river bed, narrow and shallow at the source, wider and deeper downstream (from flow and distance), with banks no steeper than bank_slope_deg blended into the ground, and lays a sloping water surface along it. Always use this for a river or a stream: never dig a furrow with terrain_brush. Place the source high up (on a mountain side, a hill). waypoints makes the river pass through points you choose, in order, before it goes on by itself: between two of them it takes the cheapest natural way, and where the ground rises the bed is dug through so the water never flows uphill (no deeper than max_cut_m). Where the water falls steeply (cascade_slope_deg, cascade_min_height_m) it makes a waterfall with foam and a pool at its foot. A river that reaches another river stops there and joins it (a confluence: ends_in river, joins gives that river's id): put a second source uphill of a river to make a tributary. The answer gives the length, the lakes made, where the river ends, its waterfalls (cascades) and its waypoints. Every setting is optional; x and z are required for a new river (with river_id, the source stays where it is unless you give them). Out-of-range values are refused with the reason; a waypoint that cannot be reached is refused too, the reason names it (waypoint 1 is the first), the depth it would need and the limit, and nothing changes.

water_add¶

Fill the hollow under a world point [x, z] with water, up to where it would overflow (an existing hollow only). For a new lake or pond, use terrain_lake instead. The lake is an object inside the terrain object.

water_set¶

Change a water object of the terrain (the sea or a lake): its surface height (higher covers more land), its rendering (realistic, or stylized for a low poly game), its look (a ready-made style first, then any setting), its swell, colours, clarity, foam and wakes. The waves you set are the ones the game's floating objects, swimmers and boats follow, in both renderings. liquid lava turns it into glowing lava (a volcano crater, a dungeon pit): opaque, no waves, nobody swims or floats in it, what touches it gets lave.contact (the health module turns it into damage), moving objects that fall in sink and vanish. Its rendering (realistic or stylized) follows the same setting as water. For a lake, outline reshapes it by hand: the shore passes through the points you give (a smooth closed curve), the basin is dug under it and the banks are cut or built up around it so the water stays inside, never overflowing nor floating; surface_y and depth_m on a lake redo the basin the same way. The answer gives the lake's outline (one point per handle the user sees in the editor): to move, add or remove one, give the whole new list. For the sea, coast reshapes a stretch of its shore the same way: an open line of points the coast passes through, with a gentle beach (beach_slope) dug below the water on the sea side and raised above it on the land side, the ground beyond and the map elsewhere untouched; its two ends stay anchored. Undoable in one step.

water_remove¶

pose_layers_get¶

Read a skinned model's skeleton and its pose layers. A pose layer is a hand correction added on top of the model's animations: a few bones turned by an angle (degrees around the character's own axes at rest, facing +Z: x points to its left, y up, z forward; +x leans an upward bone such as the back or neck forward, and swings a hanging arm backward: -x brings a hanging arm or leg forward). pose_layers_set¶

Replace all the pose layers of a skinned model, as one undoable step (read them first with pose_layers_get, change what is needed, send the whole list). Each layer: name, clip (a clip name, none for every clip, "@conduite" for the seated vehicle pose), weight 0..1, enabled, bones {bone name: [x, y, z] degrees}, positions {bone name: [x, y, z]} to move a point (the hips, or any bone: its children follow and the bone above it stretches) in model units, around the character's axes (e.g. [0, -0.1, 0] on the hips crouches by 10 cm on a model in metres), and optionally mirror "left_to_right" or "right_to_left" to copy one side onto the other. Small angles (5 to 30 degrees) are usually enough. move [{bone, by: [x, y, z] in the units of rest_position, mode: point|parent|membre, bend: auto|forward|backward, t: seconds}] moves a point as the editor's Move gizmo does, seen on the layer's clip at t (the rest pose without clip): point moves that bone alone (a position offset), parent turns only the bone above it (its length kept), membre (default) bends the limb (two bones) or turns the trunk; the layer then gets the angles and offsets. Create, replace or remove a move (skeleton animation) of a skinned model, as one undoable step. It is saved as animations/<name>.wmanim and plays like any clip of the model, under its name: in the player animation graph, the systems' animation settings (gathering, combat, enemies, dialogue...), timelines, game.play. bones: {bone name: {rotation: [{t: seconds, v: [x, y, z] degrees, ease: linear|smooth|step}], position: [{t, v: [x, y, z]}]}}: rotations around the character's own axes at rest, relative to the rest pose (like pose layers; small angles, 5 to 40 degrees); position (usually the hips; on any bone it moves that point alone, the bone above it stretches) in model units. skeleton_fix_get¶

Read a skinned model's skeleton at rest and its corrections. Many models (above all auto-rigged ones: Meshy, Mixamo auto-rig) have joints placed beside where the limb should bend: a knee behind the leg, an elbow inside the arm. A correction moves or turns a joint inside the model at rest without moving the model (the skin stays where it is), removes a joint (its skin goes to its parent) or adds one (an attach point for a weapon, or a bone that takes the skin around it). Every animation then bends around the corrected joints. Returns each bone (name, parent, role, rest position in model units, the same units as move and position), the skeleton size, and the current correction.

skeleton_fix_set¶

Correct a skinned model's skeleton, as one undoable step; the model file is never changed (the correction is stored in the project, per model, and follows the model when it is renamed). Read the bones first with skeleton_fix_get. Operations, all optional, applied in this order: reset (true: back to the original skeleton, before the others); restore (bone names: their correction and removal are undone); place ({bone: [x, y, z]}: put the joint at this rest position, in model space and model units; its children follow unless alone); bones ({bone: {move: [x, y, z] model units, turn: [x, y, z] degrees around the character's axes, alone: true to leave its children where they were}}: replaces that bone's correction); remove (bone names: the joint disappears, its skin goes to its parent, its children are attached to the parent at the same place; the root cannot be removed); add ([{name, parent, position: [x, y, z] rest position in model units, skin: true to take the parent's skin beyond it, so it bends that part like a tail tip; without skin it is an attach point for game.attach / hand_bone}]). Animations of the file, borrowed animations, .wmanim motions and pose layers then bend around the corrected joints. skin_method (auto, linear, volume): how the bones of a vertex blend. volume (dual quaternions) keeps the thickness of a bent joint and does not collapse a twisted bone; linear is the classic blend, which pinches bent joints; auto (the default) is volume. It is kept by reset.

skeleton_create¶

Create a skeleton for a model that has none (a statue, an animal imported without bones, a free model), so it can be animated; the model file is never changed (the skeleton is stored in the project, per model, and follows the model when it is renamed or moved). Either shape, a template fitted to the model from its bounds and the spread of its vertices and volume (front/back axis, up, leg height, head, an open mouth): "quadruped" (Hips, Spine, Spine1, Spine2, Spine3 the chest, Neck, Neck1 (Neck2 for a long neck), Head, Jaw, front legs LeftArm/LeftForeArm/LeftHand (+LeftShoulder with leg_bones 4), hind legs LeftUpLeg/LeftLeg/LeftFoot (+LeftToeBase), Right..., Tail chain; ears optional), "biped" (Hips, Spine..., Neck, Head, Jaw, LeftShoulder/LeftArm/LeftForeArm/LeftHand, LeftUpLeg/LeftLeg/LeftFoot/LeftToeBase, Right...), "chain" (a tail, a tentacle, a plant: chain_bones bones along the model) or "single" (one bone: a door, a chest; place it on the hinge); or bones, your own list [{name, parent (empty for the first, the root), position [x, y, z] at rest in model space and model units, tip: true for the end of a chain (no skin)}]. The names are standard, so animations of other skeletons can be borrowed. Until skeleton_bind, the whole model follows the root. Then: read the joints with skeleton_fix_get, move the misplaced ones with skeleton_fix_set (place), check them, and call skeleton_bind. One undoable step; replace: true replaces a skeleton created before.

skeleton_bind¶

Attach the skin of a model to the skeleton created for it with skeleton_create: compute the weight of every vertex on the bones, by the distance measured inside the model's volume (not straight across: the upper teeth do not follow the lower jaw across an open mouth, a leg does not take the skin of the next one), 4 bones at most per vertex, smooth at the joints. The joints moved, removed or added with skeleton_fix_set since become the created skeleton. Call it again after moving joints. One undoable step. Takes a moment on a large model. softness (0 to 1, 0.5 by default): how wide the transitions between two bones are, the weights spread along the surface; 0 gives sharp transitions, higher values soften folds at the joints. It is kept for the next skeleton_bind.

game_run¶

Play the game without a window, with scripted inputs, and report what happened: position, jumps, animation states, and what the scripts did: errors, game.log lines, HUD contents, objects left per tag, events sent (counted by name, and per target for events with a cible field, with the first and last step: hits taken before falling), what the characters driven by scripts did (metres walked, still present or not, the step they were removed), the videos that played (file, full screen or in the HUD, seconds watched, and whether they finished, were skipped or stopped), and the outcome (won or lost, at which step). The same inputs always give the same result. A segment with fight plays like a simple player: it walks to the nearest object carrying fight.tag (a system counts: @ennemis) that is still there and has not received sante.mort, and presses the attack when in reach. The report's fight part lists each target it struck: its first press, how many presses, and the step it fell (sante.mort, or removed), so the time an enemy takes to fall does not depend on the game's events. Use it to measure a fight: how long an enemy takes to fall, how long the player survives. A segment with no move and no action measures what happens when the player does nothing. Each input segment holds for a number of simulation steps (60 per second by default). move is [right, forward], relative to the camera, which starts behind the character. capture_steps returns an image of the game at those steps (4 at most); while the game shows the cursor, the image draws it where the segment put it. Times are measured on this machine and vary a little between runs: compare scripts with each other, and optimise the ones at the top. To understand a bug without adding game.log lines, use inspect: at each point (script, line, from step), the game notes the script's variables just before that line runs (locals of the function and of its callers, the script's globals, shared) and goes on; scripts.inspections returns them, or reached: false if the line never ran. The performance part gives the game's real memory and loading times: loading_ms (scene read, game ready, first frame), memory at each of those moments and at the end (working_set_mb: main memory used, private_mb, their peaks; game.models_cpu_mb: the models in main memory). Compare it to the game's performance targets (world_set performanceTargets). With measure_frames, the same inputs are played once more, drawn at 1920x1080 without vsync in the quality of the performance targets, in the background, and the report adds frame_time: median_ms, p95_ms, p99_ms, slowest_1_percent_ms and slow_frames (over the target's frame budget, 16.7 ms at 60 fps; very_slow_frames over twice that), counted after the first 2 seconds (loading); slowest_frames (their step, and their simulation, processor rendering and graphics card times); the bottleneck (family: simulation, cpu_render or gpu, with its largest part); simulation (step_ms, the average simulation step, its largest parts, slow_steps and the worst one with its step and part), cpu_render (the sum of its medians and its largest parts) and gpu (median and its largest passes, such as shadow_cascades, opaque, rt_denoise), and drawing (gpu_driven: the graphics card sorted the objects itself; cpu_draw_calls_median and cpu_draw_calls_p95: the processor's draw orders for objects; draw_calls_p95: the draws the card made; cull_ms_median: the card's sorting time). The report's scripts.players.guests lists each one: where they are, how far they walked, what they drive, whether they swim, have a menu open, and their own HUD (hud: key -> text). The same inputs give the same game.
