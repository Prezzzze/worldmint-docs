Dialogue¶

Un personnage qui parle quand on l'utilise : ses répliques s'affichent une à une, avec les réponses du joueur en boutons. Une réponse mène à une autre réplique et peut envoyer un événement, auquel le Déclencheur ou un script réagit. Des tests (un objet porté, une marque, les conversations déjà eues) choisissent ce qu'il dit.

Événements¶

Les descriptions viennent du code et sont en anglais, la langue de travail de l'agent.

Ce qu'il annonce¶

Événement Champs Description
dialogue.debut cible (id) A dialogue window opened: cible is the character who talks.
dialogue.choix cible (id), choix (number), texte (text), etiquette (text) The player chose an answer in a dialogue: choix is its rank among the answers shown (from 1), texte its text, etiquette the label of the line it answered (empty if none). Sent before the answer's own event, if it has one.
dialogue.marque marque (text) A dialogue set a mark: a word the game remembers (a line shown, an answer chosen). Every dialogue's conditions can use it.
dialogue.fin cible (id) A dialogue window closed: after its last line, or a choice leading to fin.
boutique.ouvrir cible (id) Ask the shop system to open the shop of cible, as if the player had used it: from a dialogue answer, a trigger, a script.

Ce qu'il écoute¶

Événement Champs Description
interaction.utiliser cible (id), joueur (id) The player used the object in reach: a door, a merchant, an item to pick up. Whoever owns that object decides what it does.
dialogue.ouvrir cible (id) Ask the dialogue system to start the dialogue of cible, as if the player had used it: from a zone, a trigger, a script.
dialogue.marquer marque (text), retirer (boolean?) Ask the dialogue system to set a mark, from a script or another system; with retirer true, to remove it. Dialogue conditions then see it.
inventaire.change objet (text), quantite (number), total (number), chargement (boolean?) The quantity of an item changed. total is the new quantity. chargement is true when a saved game gives the items back (game.load): nothing was picked up.
hud.clic cible (text), joueur (id?) A button of the HUD was clicked: pressed, then released on it; or chosen with A (Enter) while it has the gamepad or keyboard focus; or the window's back button (back = true), with B (Escape). cible is the button's key (game.hud_button), joueur the player who clicked (a guest clicks on their own computer; the host plays the click). Announced by the engine, before the scripts' on_update of that step.
langue.change langue (text) Sent by the engine when the player changes the game's language (game.set_language, the Menu options). A module redraws what it already shows: its texts go through game.t and game.language.

Dialogue (dialogue)¶

A character who talks when the player uses them: their lines show one by one in a window at the bottom of the screen, with the player's answers as buttons. Activating it activates interaction; placing it on an object places interaction there too. Use it for every talk the user asks for (a merchant, a guard, a quest giver) rather than a script.

Place it on the character with systems_attach, then fill lignes with systems_set: a list of rows, in order, read like a flowchart. Each row has a sorte:

  • replique: the character says texte. The choix rows right under it are its answers.
  • choix: an answer the player can click (texte is its button). As many as needed. condition hides it unless it is met: objet / sans_objet (condition_objet, condition_quantite), marque / sans_marque (condition_marque), visites (condition_visites: talks with this character already finished).
  • test: a question to the game, which chooses where to go.
  • Yes or no: test: "objet" (test_objet, test_quantite) or test: "marque" (test_marque), with si_oui and si_non.
  • By a number: test: "visites" (talks already finished) or test: "quantite" (how many test_objet the player carries), followed by sortie rows.
  • sortie: an exit of the number test above it: a_partir_de (from this number on, up to the next exit's; the last one counts for "and more") and suite.

How it flows:

  • The dialogue starts at the first row. Tests are crossed until a line to show.
  • suite, si_oui, si_non say where to go next: a row's etiquette (replique and test rows have one), fin to close, or empty for the row after the group.
  • An empty suite goes on to the row after only if that row has no etiquette: a labelled row starts another branch, so the talk ends before it. Give a label to every row a branch leads to, and none to the rows that simply follow.
  • marque (on a line or an answer) sets a word the game remembers, for every dialogue's tests and answers. annonce sends an event at the same moment, for a declencheur rule or a script.

A guard who loses patience, then lets in who has the key:

  1. test objet Clé, si_oui: "entre", si_non empty (the next row)
  2. test visites
  3. its exits: sortie 0 → cle, 1 → encore, 2 → rien, 3 → assez, 4 → cachot
  4. one labelled replique per branch (cle, encore, rien, assez, cachot with annonce: "cachot", entre)

Other details:

  • Answers: a line with no answer shown has a Next button, or End when nothing follows.
  • A merchant: on a character who also carries boutique (opening on use), the dialogue comes first, and its last line (the one with End) also offers "Show me your goods" ("Voir la marchandise"), which closes the conversation and opens the shop (boutique.ouvrir). If a line of the dialogue already sends boutique.ouvrir, that button is not added.
  • Gamepad and keyboard: each new line gives the focus to its first button; A or Enter clicks it, the d-pad or the arrows choose another answer. End is the window's back button (B, Escape); a line with Next or answers has none, so Escape still opens the pause there.
  • Saved games: game.save keeps the marks and the conversations already had with each character, and game.load gives them back.
  • Inventory: objet tests and conditions read the inventaire system (the kind of item, as it stores it), so add it to the game.
  • Marks from scripts: a script sets one with game.emit("dialogue.marquer", {marque = "..."}) (retirer = true removes it) and hears them with dialogue.marque.
  • Language: write every line in the user's language, and keep each line short (two or three sentences). For a game offered in other languages, the lines, answers and name go through the game's translation tables (translations_set): never write a dialogue per language.
  • Name and prompt: the name at the top is nom (empty: the object's name). Set the interaction prompt texte to "Talk" in the user's language.
  • Events: dialogue.choix (cible, choix, texte, etiquette), dialogue.debut and dialogue.fin (cible). game.emit("dialogue.ouvrir", {cible = id}) starts a character's dialogue from a zone or a script.
  • Game settings: pause (the world stops during a dialogue, on by default), and bas and largeur, as shares of the screen (where the window ends at the bottom and how wide it is; it grows upwards).
  • The map: the user sees the dialogue as a map in the editor (the character's properties, "Show the map"). It is a flowchart from Start to an End per branch, with boxes for lines, diamonds for tests, and named arrows (an answer, yes, no, "4 and more"). Labels that lead nowhere show in red there: check yours. The user can also edit the dialogue in that map (reconnect an arrow by dragging it, add or remove steps): read lignes again before changing a dialogue they may have touched.
  • Testing: in game_run, walk to the character, press interact, then click the buttons. The report's hud gives each button's area (dialogue.suivant, dialogue.choix.1...).
