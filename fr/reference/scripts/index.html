Les scripts de jeu (Luau)¶

Les scripts donnent au jeu ses règles propres. Ils s'écrivent en Luau, dans l'onglet Scripts de l'éditeur, et l'agent les écrit pour vous. Voici la référence complète, telle que l'agent la lit (outil scripts_reference) : elle est en anglais, la langue de travail de l'agent.

Game scripts are Luau, stored in the scene. They run on every simulation step, with the same result for the same inputs: there is no clock, no file or network access, and math.random is seeded.

A script may define on_start() and on_update(dt), and on_save() and on_load(state) to keep its state in a saved game (see Saving). Each script has its own global variables; the table shared is common to all scripts. An error stops that script and is listed by game_run.

Objects are designated by id (a string). Positions are vectors: vec(x, y, z), with .x .y .z, arithmetic, and vector.magnitude(v), vector.normalize(v). Y is up, metres. A rotation is a yaw in radians; 0 faces +Z.

Finding objects¶

game.player() -> id                    game.find(name_or_id) -> id or nil
game.players() -> {ids}. The character of every player: the one playing on this computer first, then, in a game with several players (the game setting Multiplayer), each guest who joined. The engine sends "joueur.arrivee" {joueur, numero, nom} when a guest joins and "joueur.depart" {joueur, numero} when they leave.
Several players: game.player() is the player whose action is being handled. A script whose first lines hold the line "-- multijoueur: par_joueur" runs once per player (the host's copy, then one for each guest who joins, with its own variables, its own HUD and its own saved state): inside it, game.player() is always its player. A listener of an event that carries a field joueur handles that player; game.each_player(function(id) ... end) runs the function once per player, as that player. Elsewhere game.player() is the host's own player: in a game with several players, say which player. An event emitted while handling a player gets joueur = that player if it has none; the per-player copies of a script only receive the events of their player, and those that name no player.
game.player_name(id?) -> the player's name (what they typed to join; "Joueur 1" for the host), nil if id is not a player    game.player_number(id?) -> 1 for the host, then 2, 3...; 0 if id is not a player (game.player_number(id) > 0 asks "is it a player?").
The controls, the mouse and the body of a player take an optional last argument, the player: game.pressed("attack", id), game.action, game.released, game.player_forward(id), game.set_player_speed(scale, id), game.set_player_can_run(on, id), game.set_player_can_jump(on, id), game.player_running(id), game.player_jumped(id), game.player_landed(id), game.player_swimming(id), game.show_cursor(on, id), game.cursor_shown(id), game.drive(vehicle, id), game.leave_vehicle(id), game.driving(id), game.active_camera(id), game.camera_view(id), game.using_pad(id), game.pause(on, reason, {actions}, id), game.paused(id). game.use_camera and game.use_player_camera take {joueur = id}. Without it: the player whose action is being handled.
game.with_tag(tag, {asleep=false}?) -> {ids}     game.near(pos_or_id, radius, tag?, {asleep=false}?) -> {ids}, nearest first
game.exists(id) -> bool                game.name(id) -> string
game.awake(id) -> bool. In a large world, objects in 256 m tiles beyond the activity radius around the player (300 m by default) are asleep: they still exist and can be read, but do not move, walk, animate or detect, and game.with_tag, game.with_system and game.near leave them out unless {asleep = true}. The engine sends "monde.sommeil" {objets} and "monde.reveil" {objets} when they fall asleep and wake up; compare game.time() on waking to catch up the time they slept. The tag "toujours_actif" (or a system listed in the game setting alwaysActiveSystems) keeps an object awake everywhere. Without "Large world", everything is awake.
game.has_tag(id, tag)   game.add_tag(id, tag)   game.remove_tag(id, tag)
game.distance(a, b)                    game.line_of_sight(a, b) -> bool, blocked by colliders. a and b: id or vector.

Moving and changing objects¶

game.position(id) -> vector            game.set_position(id, v). Moves its collider too; teleports a character.
game.rotation(id) -> yaw               game.set_rotation(id, yaw)      game.face(id, pos_or_id)
game.bounds(id) -> low, high or nil. The box it fills in the world, what it contains included, measured on its models (hidden ones too): low.y is its foot, high - low its size. nil if it has no model. Never guess a model's size: measure it.
game.scale(id) -> vector               game.set_scale(id, number_or_vector). What it contains follows, along its own axes, as in the editor: their place, size and collider; the player put inside it moves with it, at their own size.
game.go_to(scene, arrival?). Goes to another scene of the game (a building's inside, a cave, the next level), after a fade to black, at the object named arrival (an empty marker placed there), or where the player stands in that scene. Scripts keep running and keep their variables; the scene left stays as it was. Sends "scene.change" {depuis, vers} once there.
game.scene() -> name of the current scene    game.scenes() -> {names}. A scene's name is its file name, without folder or extension.
game.visible(id) -> bool               game.set_visible(id, bool)            game.set_solid(id, bool). false: it stops nobody any more, but stays visible (a tree falling).
game.effect(id, kind, {duration=1, away_from=pos_or_id, after="destroy" or "hide"}?). The engine animates it around its base, whatever the model: "fall" (tips over, away from away_from), "collapse" (breaks into pieces of its own model that fall in a heap), "shrink", "burst" (breaks into pieces that fly out, bounce and fade), "shake" (trembles, then comes back). after="destroy" removes it at the end; after="hide" hides it and puts it back as it was, so it reappears upright when shown again. What it contains (its children) follows it, as with game.set_scale, and comes back with it.
game.effect(preset, pos_or_id, {size=1, color=vec, amount=1, duration, loop=false, direction=vec, light=true, light_intensity=1, light_shadows=true}?) -> handle. "feu", "explosion", "magie", "etincelles" and "impact" also give their own light (it follows the effect, flickers with a fire, grows with size, casts shadows for "feu", "explosion" and "magie"): light=false removes it, light_intensity multiplies it, light_shadows=false keeps it without shadows. It changes nothing in the game. Particles, simulated by the game (the same game gives the same particles) and drawn by the renderer. preset: "eclats" (chips; on an object they take its colour), "eclats_bois", "eclats_pierre", "poussiere" (dust spreading on the ground), "feu" (flames with a little smoke and sparks: a campfire at size 1, a torch at 0.4), "fumee", "explosion", "etincelles", "impact" (a hit: a flash, sparks, dust), "pluie", "neige" (falling from a disc around the place: size widens it), "magie". On an object, a looping effect follows it. size scales the whole effect; amount the number of particles; duration in seconds (loop: 0 runs until game.stop_effect). direction: where chips or sparks fly (on an object, chips jump from the spot nearest the player, in its colour, toward the player). The report counts them under particles.
game.stop_effect(handle). It stops emitting; its particles end their life.
game.object_effect(id, on). Starts again (true) or stops (false) the effect an object carries with the "particules" system (a campfire lit or put out), and stops the looping effects scripts put on it.
game.decal(image, pos_or_id, {size=1, normal=vec(0,1,0), angle=0, opacity=1, color=vec(1,1,1), life=0}?) -> handle. Projects an image on the surfaces under it: a footprint, an impact, a stain, a puddle, a sign. image: "tache", "impact", "brulure", "flaque", "pas", "trace", or an image file of the project (PNG, JPEG). normal: the surface it lies on (up for the ground, a wall's outward direction). angle: radians around the normal. life: seconds before it fades, 0 to keep it. A game keeps a limited number of decals: the oldest disappears to make room. game.remove_decal(handle) removes one. The report counts them under decals.
game.parent(id) -> id or nil             game.children(id) -> {id}. Moving, turning, scaling, hiding, cloning or destroying a parent carries its children along.
game.clone(id, pos, {tags={...}}?) -> new id. Clones a template (usually hidden, with visible: false), which keeps tags, collider, animations and systems; the clone is visible. A vehicle (car, motorbike, boat) clones into another vehicle you can drive, with its wheels.
game.destroy(id). Removes it and its collider: a door or a wall can open that way. Not the player.
game.attach(id, holder, {bone=, offset=vec(0,0,0), rotation=vec(0,0,0), like=}?). Holds an object on a bone of an animated character (the player, another player, a character): an axe in the hand, a torch, a bag on the back. It follows the bone as the character walks, runs, strikes or chops, and no longer blocks anything. bone: a bone of the holder (read them with asset_info); without it, the bone that holds things, found by measuring the skeleton (game.hand_bone). The object is placed on the bone at rest, offset (metres) and rotation (degrees) counted along the bone's axes. like: an object already placed on a bone in the editor (a hidden axe set in the hand by hand): its exact place on its bone is reused. A copy held this way is not kept by game.save: put it back in the hand after game.load (the inventaire system does it for the item held).
game.detach(id). Lets go of it: it stays where it is, free.
game.hand_bone(id) -> bone name or nil. The bone of a character that holds things: a bone made for it under the right hand if the model has one (its name says slot, grip, weapon, prop...), else the right hand, found by its name (hand_r, RightHand, mixamorig:RightHand...) or by the shape of the skeleton. Nothing is assumed of a pack.
game.pool(template, count). Prepares count copies of a template without children, once, in on_start. game.clone then takes one, and game.destroy gives it back, which avoids rebuilding the world's list each time. Use it for what appears and disappears often: projectiles, coins, waves of enemies. A copy given back has gone for the game (game.exists is false), but its id can come back with a later game.clone: do not keep ids of destroyed objects. If the pool is empty, game.clone makes a new copy as usual.

Characters¶

Objects that walk on the ground, stopped by colliders and by each other, with gravity

game.character(id, {radius=0.4, height=1.8, turn_speed=540, idle="Idle", walk="Walking_A", run="Running_A", run_above=3.5, feet=false, feet_height=0.5, mass=70})
  Makes it a character. With clip names, it plays them by itself according to its actual speed. feet=true sets its feet on the real ground (slopes, steps), its hips lowered as needed, if its skeleton has legs the engine recognises; feet_height is the largest gap corrected, in metres. mass, in kg (1 to 10000): how hard thrown or falling objects knock it, and how heavy what it pushes feels; the player's is in player_set (mass).
  strafe=true: it no longer turns towards its movement but keeps the facing game.face or game.set_rotation gives it (a guard circling the player while watching him), and walks sideways or backwards with walk_directions and run_directions = {back=, left=, right=, forward_left=, forward_right=, back_left=, back_right=} (clip names, all optional): blended by direction, on 8 directions when the diagonals are given, 4 otherwise; a missing back plays walk in reverse, a missing side plays walk.
game.walk(id, velocity). Call on each step it should move, in m/s. It turns towards its movement. Without a call, it stops.
game.walk_to(id, pos_or_id, speed?) -> "moving", "arrived", "blocked" or "asleep". Call on each step instead of game.walk: it follows the walkable areas (the terrain and the objects with a collider: around walls, up gentle slopes, under bridges) to reach the place, or follows an object. "arrived": right next to it. "blocked": no way there (the game_run report says why); it tries again every second. "asleep": far from the player in a large world, it waits until it wakes up (see game.awake). On the way, walkers avoid each other, the player and the other characters (game settings, navigation avoidance). It uses the walkable areas of the smallest character size it fits in (its radius and height, game settings navigation sizes): a giant does not squeeze through a small door. When an object with a collider is placed or removed (a tree cut down, game.set_solid), the walkable areas around it are redone in the background and used about 0.1 s later; an object that moves counts once it has stood still for 0.5 s (a shake or a falling copy changes nothing). Nothing to do in a script: never rebuild or wait for it.
game.path(a, b) -> {points} or nil. The way around obstacles from a to b, along the walkable areas, the last point being b (or the nearest walkable point to it). a and b: id or vector.
game.push(id, impulse). A knockback that fades quickly; works on the player too. On a moving object (Physics system), a blow that changes its speed by impulse, in m/s, whatever its mass: game.push(crate, vec(0, 6, 0)) throws it up.
game.velocity(id) -> vector, in m/s: the player, a character or a moving object. Zero for an object that does not move by itself.

Physics: objects carrying the "physique" system (modules_add, then systems_attach on objects or a group) fall, roll, slide and are pushed by the player and characters walking into them: crates, barrels, balls, rocks. Their shape wraps their model (forme: boite, boule or cylindre); masse, frottement and rebond are per-object settings. The engine moves them: read where they are with game.position, place one with game.set_position (it starts again at rest), throw one with game.push. One that falls out of the world disappears. Characters' paths ignore them, since they move.

Zones: objects carrying the "zone" system announce "zone.entree" {cible = the zone, qui = who entered} and "zone.sortie" {cible, qui} when something enters or leaves their box. Its detecte setting says who counts: joueur (default), personnages (the player and characters), objets (moving objects), tout. Usually an invisible box (visible: false): a zone works hidden. game.set_solid(zone, false) switches it off. A pressure plate, a trap, a finish line, a ball in a goal.

Joints, vehicles, ragdolls (systems "articulation", "vehicule", "chiffon"¶

Set them with systems_set, the engine runs them):

game.joint_open(id), game.joint_close(id). A hinge or slider's motor drives it to its open or closed stop. game.joint_break(id) makes it give way.
game.joint(id) -> {kind, position, broken} or nil. position: degrees for a hinge, meters for a slider. "articulation.cassee" {cible, autre?} when one breaks.
game.drive(id) puts the player at the wheel of a vehicle (a fallen motorbike is set back on its wheels); game.leave_vehicle() gets them out; game.driving() -> the vehicle driven, or nil. The player also gets in and out with "interact".
game.vehicle(id) -> {speed (km/h), driven, flipped, boat, aground, motorbike, fallen, lean} or nil. aground: a boat resting on the bottom or the shore. fallen: a motorbike lying on its side; lean: how far it leans, in degrees (positive: to its right). "vehicule.monte" and "vehicule.descendu" {cible, qui}; "vehicule.tombe" {cible, qui?} when a motorbike falls over (qui: its rider, thrown off).
game.ragdoll(id, on, push?). An animated character falls limp (on) or gets back up (false), push a vec in m/s. game.ragdolled(id) -> true while down. "chiffon.tombe" and "chiffon.releve" {cible}.

Animation (skinned objects)¶

game.clips(id) -> {names}              game.clip_length(id, clip) -> seconds or nil
game.play(id, clip, {loop=true, speed=1, fade=0.15}?). With loop=false, the clip plays once, then the character returns to its usual animation. On the player, this temporarily takes over from the animation graph: use it for attacks.
game.pose_layer(id, layer, weight). Pose layers are hand corrections of a model's animations (pose_layers_get/pose_layers_set): weight 0 switches one off, 1 on (true/false work too), in between a part of it; for this character only, until the game ends. A guard who stands straighter while alert, a wounded arm hanging lower.

Player and inputs¶

game.action(name) -> held              game.pressed(name) -> pressed on this step       game.released(name) -> let go on this step
  Actions are the game's controls (controls_list, controls_set): one per key the game uses, never a key read directly. By default "attack" (left mouse button) and "interact" (E); modules add theirs (block, heal). Moving, running, jumping and pausing are controls too: move_forward (w), move_back (s), move_left (a), move_right (d), run (lshift), jump (space), pause (escape). Escape does not close the game: if no script reads "pause", it frees the cursor.
game.bindings() -> {action = key}      game.bind(action, key). Changes a key during the game, for a key configuration menu. A gamepad button (pad_a, pad_b, pad_x, pad_y, pad_lb, pad_rb, pad_lt, pad_rt, pad_start, pad_back, pad_ls, pad_rs, pad_up, pad_down, pad_left, pad_right) changes the gamepad binding and leaves the key.
game.pad_bindings() -> {action = button}. By default: jump pad_a, attack pad_x, interact pad_y, run pad_lt, pause pad_start. The left stick moves, the right stick turns the camera.
game.action_label(action) -> text to show in a prompt: the key ("E") on keyboard, the button ("Y") when the player plays with a gamepad.
game.action_name(action) -> what the action is called for the player, in their language ("Jump", "Block"): for a key configuration menu.
game.last_key() -> the key pressed on this step, or nil. Key names: letters, digits, space, lshift, mouse_left, mouse_right...
game.player_forward() -> vector        game.set_player_speed(scale). 0 stops the player, 1 is normal.
game.set_player_can_run(bool)          game.set_player_can_jump(bool). Takes running or jumping away without stopping the walk: tiredness, a heavy load.
game.player_running() -> bool          game.player_jumped() -> bool. On the last step: the player moved while running; the player left the ground by jumping.
game.player_landed() -> bool. On the last step: the player touched the ground again after a jump or a fall.
game.player_swimming() -> bool. In water deeper than about half its height, the player swims: it floats with its head out, moves at its swim speed, and cannot jump. The animation graph gets a "swimming" parameter (1 or 0) for a swim state.
game.footsteps() -> {ids}. Those whose foot touched the ground on the last step, read from their walk or run animation: the player and animated characters.
game.ground(id) -> id or nil. The object under its feet (one with a collider): a floor of stone, a wooden bridge. On a terrain: the biome object (Forest, Snow...), or the water object (Sea, Lake) when it stands in water.
game.water_depth(id) -> metres of water where it stands, 0 on dry ground. For wading, slowing down, drowning: the engine itself only draws water.
Moving, running, jumping and the camera are handled by the engine: see player_set.

Placed lights¶

Objects created with a light field (a bulb, or a spot that points down from the object). Hiding one with set_visible switches it off too.

game.light(id) -> {on, color, intensity, range, angle, kind} or nil if it is not a light. color is a vector (r, g, b), from 0 to 1.
game.set_light(id, {on?, color?, intensity?, range?, angle?}). Only the given fields change: game.set_light(lamp, {on = false}) switches it off, {color = vec(1, 0.2, 0.1)} makes it red. Fails if the object is not a light. game.save keeps it: no need to save lights yourself.

The sun and the sky of the scene being played¶

A day and night cycle, a storm. Colors are vectors (r, g, b), from 0 to 1.

game.environment(authored?) -> {sun_direction, sun_color, sun_intensity, sky_color, ground_color, background, exposure, fog_distance, fog_color, auto_exposure, auto_exposure_brighten, auto_exposure_darken, auto_exposure_seconds}. sun_direction points toward the sun (y up: high in the sky). authored=true gives the scene as the creator lit it, whatever the game changed since.
game.set_environment({...}). Only the given fields change, from the next frame: game.set_environment({sun_intensity = 0.1, sky_color = vec(0.05, 0.07, 0.15)}) makes it night. game.save keeps it. The "jour_nuit" system turns the sun and the sky for you: prefer it to a hand-written cycle. Automatic exposure (auto_exposure, on by default; auto_exposure_brighten 1 to 64, auto_exposure_darken 1 to 64, auto_exposure_seconds 0 to 30) brightens dark rooms like an eye getting used to them; it only brightens relative to the light still there, so a night made with set_environment stays dark.

Placed cameras¶

Objects created with a camera field, which show the game from where they stand. While one is active, the mouse does not turn the view, and the player moves relative to what it shows.

game.use_camera(id, {blend=0, joueur=id}?). blend is a smooth move in seconds; 0 cuts at once. Fails if the object is not a camera. With several players, only that player (joueur, or the player whose action is being handled) sees through it.
game.use_player_camera({blend=0}?). Back to the camera that follows the player.
game.active_camera() -> id, or nil for the one that follows the player.
game.camera_view() -> the kind of view the player has: "fixed" (a placed camera is active), "top_down" (the camera that follows the player never rises below 45 degrees: its lowest tilt, in the player settings, is 45 or more), "first_person" (its distance is 1 m or less) or "third_person". To aim like the game is seen: the centre of the screen with a character, the cursor from above.
game.using_pad() -> true while the player plays with a gamepad (always false for a guest, for now).
Move or turn a placed camera like any object, with game.set_position and game.set_rotation. If it is destroyed, the game returns to the player's camera.

Animations made by hand and cutscenes (timelines of the scene, made in the editor or with timeline_set)¶

The engine plays them: objects take their keyframes, a cutscene shows its cameras, moves its characters, plays its sounds and subtitles, takes control away from the player and gives it back at the end.

game.play_timeline(id, {speed=1, from=0, end_event=nil}?). Plays it from the start (or from seconds); playing it again restarts it. end_event: an event name sent when it ends. Fails if there is no such timeline, or if another cutscene is playing.
game.stop_timeline(id). Stops it where it is, objects left as they are.   game.timeline_playing(id) -> bool.
Sends "timeline.debut" {timeline, sorte} when one starts, and "timeline.fin" {timeline, sorte, passee, arretee} when it ends (passee: the player skipped the cutscene; arretee: stopped by game.stop_timeline). Its own events are sent with {timeline}.

On screen¶

Coordinates and sizes are fractions of the screen, from the top left. The key identifies an element: calling again updates it, in place. Elements are drawn in the order they were first created: create a background before what goes on it.

With several players, each player has their own HUD: an element made by a per-player script, inside game.each_player, or given {joueur = id}, is seen by that player only; one made by a script for the whole game is seen by everyone, even while it answers one player's event (say {joueur = game.player()} to show it to that player). A guest's HUD is sent to their computer and laid out there, at their screen's size; their clicks come back as "hud.clic" {cible, joueur}. Videos stay on the host's screen.
game.hud_text(key, text, {x=0.5, y=0.5, size=0.035, color=vec(1,1,1), alpha=1, align="center", w=nil}?). align: left, center, right. With w, the text wraps at word boundaries to that width.

Interface building blocks¶

Menus, shops, dialogues, chat, name entry. Let panels place elements instead of writing positions by hand.

game.hud_panel(key, {x=0.5, y=0.5, w=nil, h=nil, align="center", color=, alpha=, layout="column", columns=2, gap=0.01, padding=0.015, scroll=false, parent=nil}?)
  A background that places its children, in the order they were created, inside its padding and with gap between them (gap and padding are fractions of the screen height, the same on both sides). Without w or h, it fits its content.
  layout "column": one under the other; a child without w takes the inner width (a text wraps to it). "row": side by side, centred in height. "grid": columns cells per row, all the same width.
parent=key, accepted by every hud_ function: the element goes in that panel, which must exist already; its x and y are ignored. Panels nest.
shape="circle", "diamond", "triangle", "square" or "star": the panel is drawn as that shape in its frame, a map marker; rotation turns it, clockwise in radians (a triangle points up at 0: an arrow).
scroll=true with a h: when the content is taller, the mouse wheel over the panel scrolls it (the wheel then does not reach the game), with a thin scroll bar; its children are cut at its frame, neither drawn nor clickable outside it. Calling hud_panel again on each step keeps the scroll.

On a gamepad, once selected: the d-pad moves the cursor, A validates, B leaves. While a field is selected, the player does not move and no control fires. text only sets the value when the field is created: calling hud_input on each step keeps what was typed. max: most characters, 0 for no limit.
game.hud_value(key) -> text or nil. What a field holds (or an element's text).   game.hud_set_value(key, text)
game.hud_focus(key) selects a field; on a button, gives it the gamepad and keyboard focus (seen when the player uses them). game.hud_focus(nil) leaves both.
game.hud_focused() -> key or nil. The field being typed in, or the button with the visible gamepad or keyboard focus.

React to them with game.on instead of comparing game.hud_at() yourself.
Gamepad and keyboard, with nothing to write: while the game shows the cursor, the engine finds the buttons of the window in front (the last created element without parent, a panel usually, that holds buttons). The d-pad, the left stick, the arrow keys and Tab move a visible focus from one button to the next by their place on screen (held, it repeats); A or Enter clicks it; B or Escape clicks the window's back button. A window that opens gives the focus to its first button when the player plays with a gamepad; with a keyboard, the first arrow shows it. A list that scrolls follows the focus. While a window has the focus the player does not move, and the controls bound to these buttons (jump on A, a potion on the d-pad) do not fire. The mouse hides the focus and keeps working as before.
game.hud_navigation(false) leaves the gamepad to your script (a key configuration menu waiting for a key); game.hud_navigation(true) gives it back.
Rich text, in hud_text and button texts: [b]bold[/b], [color=#ff8800]colored[/color]. Another tag is shown as it is.
The "interface" system (modules_add): its game settings are the look of every element: panel and button backgrounds, accent color (hover, selected field, scroll bar), text color and size, corner rounding, background opacity. Values a script gives win over it.
Example: game.hud_panel("menu", {y=0.2, w=0.3}) game.hud_text("titre", "[b]Pause[/b]", {parent="menu"}) game.hud_button("reprendre", "Resume", {parent="menu"})
In game_run, a segment's text is typed into the selected field on its first step: "\b" erases, "\n" validates.

Graphics¶

What the player chooses for the picture, on top of the game settings (Window): for an options menu (the menu module does it).

game.graphics() -> {quality = "low"|"medium"|"high", upscaling = "off"|"native"|"quality"|"balanced"|"performance"|"ultra_performance",
upscaler = "none"|"dlss"|"fsr", dlss = bool, dlss_available = bool, fsr_available = bool, antialiasing = "auto"|"taa"|"smaa"|"fxaa"|"none",
shadows = "auto"|"high"|"medium"|"low"|"off", ray_tracing = "auto"|"on"|"off",
ray_tracing_available = bool, ray_tracing_heavy = bool, ray_tracing_cut = bool, indirect_light = bool}, or nil when nothing is drawn (game_run without capture). quality also sets the
particles budget. upscaler: what rebuilds the full-size picture when upscaling is not "off": "none" is WorldMint's own, "fsr" is AMD FSR 2
(sharper, every card: fsr_available), "dlss" is NVIDIA DLSS (dlss_available is true only when the creator provided NVIDIA's files and the
game enabled DLSS, on an RTX card); dlss is the older form (true when upscaler is "dlss").
antialiasing: how edges are smoothed when upscaling is "off" (any other upscaling already smooths them); "auto" follows quality (TAA in
high and medium, SMAA there in a project created before November 2026; FXAA in low), "taa" is sharp in motion but needs a redraw every frame (it turns upscaling "native" on), "smaa" is sharp
with no trail, "fxaa" the lightest, "none" keeps jagged edges.
shadows: the player's shadow quality, for the sun and every light; "auto" (default) follows quality and the scene's shadow quality,
"off" removes every shadow (the cheapest, rays included). ray_tracing: shadows drawn with rays; "auto" uses them only on a dedicated
graphics card in medium and high quality, "on" forces them, "off" never. ray_tracing_available is true only when the card has it and
the game allows it (window ray_tracing); ray_tracing_heavy is true when "on" forces it where it is heavy (an integrated chip, low
quality): tell the player the picture may slow down. ray_tracing_cut is true when the renderer turned rays off because the graphics
card's memory is full (shadows come back from shadow maps); another ray_tracing or quality choice makes it try again.
indirect_light (true by default): light bounced by surfaces (a sunlit floor lights the walls, a room is lit through its window), ray
traced with a light cache; used only in high quality with ray tracing on, it costs about 1 to 2 ms.

drawn. Not kept by itself: save the player's choice (game.save with {systems = false}) and set it again in on_start.

game.module_settings(module) -> table. The settings of a module for the whole game, as the user set them.
game.system(id, module) -> table or nil. The values of a module for this object: a module is placed on objects or groups, and each one has its own values (a boss and a skeleton do not hit alike). nil if the object does not carry it.
game.with_system(module, {hidden=false, asleep=false}?) -> {ids}. Every visible object carrying it; with hidden=true, hidden ones too (a zone is usually an invisible box); with asleep=true, those asleep far away in a large world too (see game.awake). game.emit(event, {fields}?). Announces an event: every listener runs now, in the order they subscribed, and receives the fields (an empty table if none).

Sound mixer¶

Every sound belongs to a group of the game's mixer (game settings, Sound mixer): music, effects, ambience, voice, ui, and those the user added. group names one by its id or its name ("ambience" or "Ambiance"); without group, a sound goes to effects and the music to music. Pick the group that fits: a looping fire or wind in ambience, a character's line in voice, a menu click or a pickup chime in ui. The mixer sets each group's volume, can mute it, and lowers one while another plays (ducking: music under voices). Do not lower a music by hand when a line plays: put the line in voice.

game.volume(group or "master", 0..1). The player's level, on top of the game's mix: for an options menu (the menu module does it).
game.mute(group or "master", true or false). Cuts a group, or all the sound, and brings it back (a cutscene without ambience).
game.muffle(group or "master", 0..1, {fade=0.5}?). Muffled like under water or behind a wall: 0 clear, 0.5 behind a door, 1 under water. A trigger rule can do it too.
game.sound_groups() -> {{id, name}, ...}. The mixer's groups in order, name in the player's language: for an options menu.

Videos¶

Files are MP4, M4V or MOV (H.264 video, AAC sound): find them with assets_search and kind "video". The game counts their time step by step, from the length written in the file: in game_run nothing is seen, but they start, end and announce their end at the same step as on screen, and the report lists them (videos: file, fullscreen, seconds watched, end "finished", "skipped", "stopped" or "playing").

game.video(file, {skip=true, event=nil, pause=true, volume=1, group="voice"}?) -> handle. A full-screen cutscene, over the world and the HUD, with its sound: an intro, an ending, a story moment. Its sound goes to the voice group, so the music lowers under it; give another group of the mixer if it fits better. When it ends (finished, skipped or stopped), the engine announces "video.fin" {video=handle, fichier=file, passee=true if skipped}, and also your event if given: game.on("intro_done", function(e) game.go_to("Village") end). This is how you chain what comes next.

A video inside the HUD (a screen in a menu, an animated portrait), like game.hud_image: h=0 keeps the video's real proportions. Saving the player's progress¶

game.save(slot, table) -> true, or false and a reason. slot: lowercase letters, digits, _ and -, such as "game1". The table holds text, numbers, booleans, vectors, lists and tables with text keys: the state of the game (level, position, items), not the whole world. 1 MB at most.
game.load(slot) -> table, or nil if there is none.     game.has_save(slot) -> bool     game.delete_save(slot)
Saves are kept between plays of the player's game. In game_run they stay in memory: your tries never touch the player's saves.
The systems keep their own state: game.save asks every script that defines on_save() for a table (its state: the inventory's items, the quests' progress, the shops' stocks, the dialogues' marks), and game.load gives each one back to its on_load(state). game.load called in on_start waits until every script has started. Do not save or re-add what a system keeps. The engine keeps the world too, in every scene visited: objects shown or hidden, solid or not, moved, turned, resized or pushed, destroyed (game.destroy) or copied (game.clone, game.pool), tags, lights, looping effects, decals, the active camera, timelines playing, joints, ragdolls, the vehicle driven, the player's speed and abilities. game.load puts each scene back as it was when saved; the player's own position is the game's to keep. {systems = false} as the last argument of game.save or game.load leaves them out (to read a save without resuming it).
A script of your own can do the same: function on_save() return {opened = opened} end   function on_load(state) opened = state.opened end. The state follows the rules of game.save; it is stored under the script's name.

Example of the syntax, not a model for your game¶

A dog that follows the player, and coins to collect.

local gold = 0
function on_start()
  for _, id in game.with_tag("dog") do
    game.character(id, {idle="Idle", walk="Walking_A"})
  end
end
function on_update(dt)
  local player = game.player()
  for _, id in game.with_tag("dog") do
    local to = game.position(player) - game.position(id)
    if vector.magnitude(to) > 3 then game.walk(id, vector.normalize(to) * 2) end
  end
  for _, id in game.near(player, 1.2, "coin") do
    game.destroy(id)
    gold += 1
  end
  game.hud_text("gold", "Gold: " .. gold, {x=0.02, y=0.07, align="left"})
end
