L'onglet Scripts¶

Le troisième onglet de la colonne de gauche. « Les scripts donnent ses règles au jeu : ennemis, objets à ramasser, objectifs. L'agent les écrit pour vous, et vous pouvez les modifier ici. »

Les scripts appartiennent au jeu entier, pas à une scène : ils continuent de tourner quand le joueur passe d'une scène à l'autre.

La liste¶

  • Nouveau script crée un script vide, nommé script_1, script_2..., qui contient déjà les deux fonctions de base : on_start() (au début du jeu) et on_update(dt) (à chaque pas du jeu).
  • Un clic sur un script l'ouvre.

L'éditeur de script¶

Le script s'ouvre par-dessus la vue 3D, avec son nom en haut :

  • écrivez dans la zone de texte (la touche Tab insère une tabulation) ;
  • Enregistrer le script (ou Ctrl+S dans le texte) vérifie l'écriture du script avant de l'enregistrer : une erreur s'affiche en rouge sous le texte, et le script n'est pas enregistré tant qu'elle reste ;
  • Supprimer supprime le script ;
  • la croix Fermer referme l'éditeur sans enregistrer.

Tant que vous n'avez rien changé, l'éditeur suit ce que l'agent écrit dans ce script. Une image citée par un script est copiée dans le projet à l'enregistrement.

Chaque enregistrement et chaque suppression s'annulent par Ctrl+Z.

Mettre le jeu en pause sur une ligne¶

Quand un script ne fait pas ce qu'on attend, on peut arrêter le jeu sur une de ses lignes et regarder ce qu'il contient à ce moment-là.

  • À gauche du texte, la marge montre les numéros de ligne. Un clic sur un numéro pose un point d'arrêt (un point rouge) ; un second clic le retire. Une ligne vide ou un commentaire s'arrête à la ligne suivante.
  • Lancez le jeu avec Jouer. Quand le jeu arrive sur la ligne marquée, il se met en pause juste avant elle : sa fenêtre l'indique dans son titre, et l'éditeur passe devant, le script ouvert sur la ligne surlignée.
  • À droite du texte, les variables telles qu'elles sont à cet instant : celles de la fonction arrêtée, celles des fonctions appelantes, les variables du script (celles écrites sans local) et les variables partagées (shared). Un tableau se déplie d'un clic sur sa flèche.
  • Pour reprendre :
    • Continuer (touche F5) : le jeu repart jusqu'au prochain point d'arrêt, et sa fenêtre repasse devant ;
    • Ligne suivante (F10) : exécute la ligne surlignée et s'arrête à la suivante ;
    • Entrer dans la fonction (F11) : si la ligne appelle une fonction du script, s'arrête à sa première ligne ;
    • Sortir de la fonction (Maj+F11) : finit la fonction en cours et s'arrête dans celle qui l'a appelée.

On peut poser et retirer des points d'arrêt pendant que le jeu tourne. Ils servent à l'essai depuis l'éditeur : un jeu exporté ne s'arrête jamais. Le jeu fait tourner le script tel qu'il était enregistré quand on a cliqué sur Jouer.

L'agent sait faire de même sans arrêter le jeu : il lit les variables d'un script à une ligne et à un moment donnés pendant ses essais, pour comprendre un problème sans ajouter de game.log partout.

Ce qui ralentit mon jeu¶

Pendant une partie, sous la liste des scripts, la section Ce qui ralentit mon jeu montre le temps que prend chaque script à chaque image, sur les deux dernières secondes : le plus lourd en haut, en millisecondes et en part de l'image. Les systèmes du jeu sont des scripts : ils y figurent aussi.

  • Une barre rouge signale un script qui prend plus du quart de l'image, ou qui approche d'une de ses limites (le temps d'un seul pas, ou la mémoire des scripts) : au-delà, le jeu l'arrête avec une erreur.
  • En survolant une ligne : le pire moment, la moyenne sur toute la partie, la mémoire du script et la part de son budget de temps qu'il a prise au pire. Un clic ouvre le script.
  • Après la partie, les chiffres de sa fin restent affichés.

L'agent reçoit les mêmes chiffres à chaque essai, et peut alléger lui-même le script le plus lourd.

Le langage¶

Les scripts s'écrivent en Luau, un langage simple dérivé de Lua. Toutes les fonctions disponibles (trouver des objets, les déplacer, faire marcher des personnages, afficher du texte à l'écran, jouer des sons, sauvegarder la partie...) sont dans la référence des scripts.

Un script ne modifie jamais un système : pour changer un comportement d'un système, il écoute ses événements (game.on) ou remplace un de ses points prévus pour cela (game.override). Voir les événements.
